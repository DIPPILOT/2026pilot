# Day 4 숙제 미션 — API 계약과 검토

개인 제출 / 숙제 2개 / 권장 총 90~120분. 제출 규칙은 [운영 안내](README.md)를 따른다.

학습 근거: [기존 Mission](../day4_codex_mission.md), [Summation](../day4_codex_summation.md), [추가 Skill Task](../skill_tasks/day04_skill_tasks.md).

## HW-D04-01 — 다른 팀이 구현할 수 있는 API 계약을 제출하라

- 영역: HYBRID
- 기술 Skill: TECH-API, TECH-DDD
- AI Skill: AI-CTX, AI-REV, AI-DOC
- 예상 시간: 45~60분

### 문제 상황

프론트엔드 팀이 영상 조회·재생 시작·Campaign 생성·광고 요청 기능을 구현해야 한다. 백엔드 코드는 아직 없고, 양 팀은 계약 문서만으로 병렬 작업해야 한다.

### 해결해야 할 문제

4개 기능의 Endpoint를 책임 Domain별로 설계하라. Method·경로·입력·응답·상태 코드·인증 및 소유권 조건을 적고, 각 API에 정상 1개와 실패 1개 예시를 제공하라. 중복 재생/광고 요청 정책과 ERD 필드 대응을 설명하라. 서버 구현은 요구하지 않는다.

정책에 여러 답이 가능하다. 선택한 답의 근거와 제외한 대안을 최소 1개 설명하라. 문제에 없는 정보는 가정으로 표시하라.

### 제출물

api_contract.md 및 openapi.yaml: 4개 API 계약과 예시. 선택한 OpenAPI 버전을 명시하라.

본인이 사용한 AI 질문, 핵심 응답, 수용·수정·거절 판단을 과제 폴더의 ai_review.md에 제출하라. AI 검토를 위해 완성된 답을 외우거나 제공된 프롬프트를 복사하는 대신 자신의 검토 질문을 작성한다.

### 평가 기준 — 50점

계약 완전성 20점; Domain·데이터 대응 15점; 오류·중복 정책 10점; AI 검토와 자기 판단의 증거 5점. 각 항목은 제출된 증거의 완전성과 일관성에 따라 부분 점수를 부여한다.

### 제출 전 자기 점검

- 요구한 개수와 파일을 충족했는가?
- 결과를 직접 설명할 수 있으며 선택의 근거가 있는가?
- 도식·예시·문서가 서로 같은 정책을 표현하는가?

## HW-D04-02 — 깨진 계약의 호환성을 회복하라

- 영역: HYBRID
- 기술 Skill: TECH-API, TECH-QA
- AI Skill: AI-CTX, AI-REV, AI-DOC
- 예상 시간: 45~60분

### 문제 상황

기존 응답은 {"campaign_id":"C1","budget":1000,"status":"ACTIVE"}다. 새 백엔드는 {"id":1,"budget":"1000 KRW","status":"RUNNING"}을 반환하고 실패도 HTTP 200으로 응답한다. 기존 화면은 campaign_id를 링크에 사용하고 budget으로 숫자 비교를 하며 ACTIVE일 때만 중단 버튼을 표시한다.

### 해결해야 할 문제

영향을 4개 이상 찾아 분류하라. 전환 전략과 수정 계약을 정하고 구버전 소비자의 동작을 설명하라. 정상·권한 없음·잘못된 입력·기존 소비자·중복 요청을 포함한 계약 테스트 5개를 입력과 기대 결과로 작성하라.

정책에 여러 답이 가능하다. 선택한 답의 근거와 제외한 대안을 최소 1개 설명하라. 문제에 없는 정보는 가정으로 표시하라.

### 제출물

api_review.md: 영향표, 계약 변경안, 전환 결정, 테스트 명세.

본인이 사용한 AI 질문, 핵심 응답, 수용·수정·거절 판단을 과제 폴더의 ai_review.md에 제출하라. AI 검토를 위해 완성된 답을 외우거나 제공된 프롬프트를 복사하는 대신 자신의 검토 질문을 작성한다.

### 평가 기준 — 50점

구체적인 소비자 영향 20점; 전환 전략 15점; 테스트 관찰 가능성 10점; AI 검토와 자기 판단의 증거 5점. 각 항목은 제출된 증거의 완전성과 일관성에 따라 부분 점수를 부여한다.
