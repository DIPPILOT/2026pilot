# 기회 정의

## 1. 문서 목적

이 문서는 SW 랜딩 서비스가 어떤 문제를 해결하고, 누구에게 어떤 결과를 제공할지 정의합니다. 아래 내용은 초기 가설이며 사용자 인터뷰와 운영 데이터로 수정해야 합니다.

## 2. 기회 가설

지역의 SW 기업과 공급 역량은 여러 기관, 기업 소개서, 지원사업 페이지에 흩어져 있습니다. 수요자는 자신의 과제에 맞는 기업을 빠르게 비교하기 어렵고, 공급자는 실제 상담으로 이어지는 방식으로 역량을 설명하기 어렵습니다.

서비스의 기회는 단순한 홍보 페이지가 아니라 다음 흐름을 짧게 만드는 데 있습니다.

```text
수요자가 문제를 인식함
  → 적합한 SW 역량과 사례를 확인함
  → 신뢰할 근거를 검토함
  → 상담 또는 연결을 요청함
  → 운영자가 적합한 공급자와 연결함
```

## 3. 핵심 고객

### 3.1 1차 고객: SW 도입 수요 기업

- 디지털 전환이나 신규 서비스 개발이 필요하지만 적절한 공급자를 모르는 기업
- 비교 가능한 정보, 실제 구축 사례, 예상 진행 절차가 필요한 실무 책임자
- 긴 제안 절차 전에 적합성을 빠르게 판단하고 싶은 의사결정자

### 3.2 2차 고객: 지역 SW 공급 기업

- 보유 기술과 레퍼런스를 잠재 고객에게 알리고 싶은 기업
- 단순 노출보다 조건이 맞는 상담 기회를 원하는 영업 담당자
- 공공 및 민간 협업 기회를 찾는 기술 기업

### 3.3 운영 고객

- 기업 정보와 사례를 관리하고 연결 성과를 추적하는 운영 담당자
- 유입, 문의, 매칭, 후속 성과를 보고해야 하는 사업 책임자

## 4. 해결할 문제

| ID | 문제 | 현재 대안의 한계 | 기대 결과 |
|---|---|---|---|
| PRD-001 | 수요자가 적합한 SW 기업을 찾기 어렵다 | 검색 결과와 기업 소개 자료가 흩어져 비교가 어렵다 | 분야와 사례를 기준으로 후보를 빠르게 이해한다 |
| PRD-002 | 공급자의 역량 설명이 기술 나열에 머문다 | 고객 문제와 성과 중심의 설명이 부족하다 | 문제, 해결 방식, 성과가 연결된 사례를 본다 |
| PRD-003 | 관심이 생겨도 다음 행동이 불명확하다 | 문의 채널과 필요 정보가 제각각이다 | 한 개의 명확한 상담 흐름으로 전환한다 |
| PRD-004 | 운영자가 랜딩 성과를 확인하기 어렵다 | 페이지 조회와 실제 매칭 성과가 분리된다 | 문의부터 연결 결과까지 단계별로 측정한다 |

## 5. 제품 약속

> 수요 기업이 자신의 문제에 맞는 지역 SW 역량을 이해하고, 신뢰할 근거를 확인한 뒤, 짧은 절차로 상담을 요청하게 한다.

## 6. MVP 사용자 흐름

1. 방문자가 첫 화면에서 서비스 대상과 가치를 5초 안에 이해한다.
2. 해결 분야 또는 대표 사례를 탐색한다.
3. 참여 기업과 지원 근거를 확인한다.
4. 상담 신청 버튼을 누른다.
5. 최소 정보만 입력해 신청한다.
6. 운영자는 신청 내용을 확인하고 후속 상태를 기록한다.

## 7. MVP 범위

### 포함

- 가치 제안이 명확한 히어로 섹션
- 해결 분야 또는 제공 역량 소개
- 대표 성공 사례
- 참여 기업 또는 파트너 신뢰 요소
- 진행 절차와 자주 묻는 질문
- 상담 신청 폼 및 개인정보 동의
- 기본 분석 이벤트와 접근성, 반응형 레이아웃

### 제외

- 공개 기업 검색·필터 플랫폼
- 회원가입과 개인 대시보드
- 계약, 결제, 정산
- 자동 추천 알고리즘
- 운영자용 대규모 CMS

## 8. 성공 지표 초안

| 단계 | 지표 | 초기 판정 기준 | 비고 |
|---|---|---:|---|
| 도달 | 유효 방문 수 | 기준선 수집 | 캠페인별 구분 필요 |
| 관심 | 핵심 섹션 도달률 | 50% 이상 가설 | 스크롤 이벤트 |
| 의도 | 주요 CTA 클릭률 | 5% 이상 가설 | 위치별 비교 |
| 전환 | 상담 신청 완료율 | 2% 이상 가설 | 유효 방문 대비 |
| 품질 | 유효 리드 비율 | 50% 이상 가설 | 운영 판정 기준 필요 |
| 성과 | 실제 연결 비율 | 기준선 수집 | 후속 CRM 또는 시트 연동 |

## 9. 검증 계획

| 가설 | 검증 방법 | 판정 기준 |
|---|---|---|
| 고객은 기업 목록보다 문제 해결 사례를 먼저 원한다 | 수요 기업 5곳 인터뷰와 두 가지 메시지 테스트 | 사례 중심 안을 선호한 응답이 과반 |
| 짧은 폼이 상담 의도를 충분히 포착한다 | 필드별 이탈률 및 운영자의 추가 질문 기록 | 완료율을 해치지 않으며 후속 연락에 필요한 정보 확보 |
| 지역성과 공공기관 신뢰가 전환에 도움을 준다 | 신뢰 요소 노출 전후 CTA 클릭 비교 | 클릭 또는 신청률 개선 |

## 10. 결정이 필요한 항목

- 서비스의 공식 명칭과 운영 주체
- 주요 수요 산업군과 지역 범위
- 소개할 SW 분야와 기업 선정 기준
- 상담 접수 후 응답 SLA
- 개인정보 보관 기간과 담당자
- 핵심 사례에 사용할 실제 성과 수치
