# 리얼 벤치마킹 PBL 평가 루브릭

## 1. 평가 방식

총점은 100점입니다. 결과물의 외형만 평가하지 않고, 관찰 근거가 문서와 구현을 거쳐 최종 비교까지 추적되는지를 평가합니다.

학생은 제출 전에 스스로 먼저 채점합니다. 각 평가 요소에 대해 아래 성취 수준을 고르고 근거 파일과 위치를 적습니다.

| 수준 | 의미 | 배점 환산 |
|---:|---|---:|
| 4 | 요구사항을 모두 충족하고 근거·예외·한계까지 설명 | 해당 항목 배점의 100% |
| 3 | 핵심 요구사항과 근거를 충족하나 일부 예외·깊이가 부족 | 해당 항목 배점의 80% |
| 2 | 결과물은 있으나 근거 연결이나 검증이 부분적 | 해당 항목 배점의 60% |
| 1 | 초안 수준이며 재현·검증하기 어려움 | 해당 항목 배점의 30% |
| 0 | 미제출, 확인 불가 또는 필수 안전 규칙 위반 | 0점 |

계산 예시: 배점 8점 항목에서 수준 3이면 `8 × 0.8 = 6.4점`입니다. 총점은 소수점 첫째 자리까지 계산합니다.

### 자기채점 기록 형식

```markdown
| 평가 요소 | 배점 | 자기 수준 | 자기 점수 | 근거 파일과 위치 | 보완할 점 |
|---|---:|---:|---:|---|---|
| 관찰 근거 | 8 | 3 | 6.4 | research/BENCHMARK_LOG.md, OBS-001~012 | URL 누락 1건 보완 |
```

## 2. 미션별 배점

| 영역 | 배점 | 핵심 평가 질문 |
|---|---:|---|
| 미션 1: 조사와 성장 가설 | 25 | 실제 관찰을 바탕으로 성장 루프를 설명했는가? |
| 미션 2: 3종 문서 | 25 | 제품·BM·기술 문서가 일관되고 추적 가능한가? |
| 미션 3: AI 기반 구현 | 30 | 문서와 일치하는 작동 가능한 흐름을 만들고 검증했는가? |
| 미션 4: 비교와 학습 | 20 | 동일 기준으로 차이를 증명하고 다음 실험을 제안했는가? |

## 3. 상세 루브릭

### 미션 1: 조사와 성장 가설, 25점

| 기준 | 우수 | 보통 | 미흡 | 배점 |
|---|---|---|---|---:|
| 폴더와 기록 구조 | 산출물 경계와 링크가 명확하고 바로 탐색 가능 | 기본 구조는 있으나 일부 파일 목적이나 링크가 불명확 | 자료와 코드가 섞이고 주요 파일을 찾기 어려움 | 5 |
| 관찰 근거 | 날짜·URL·사용자 상태·캡처가 핵심 주장마다 연결 | 근거는 있으나 일부 주장과 연결이 약함 | 기억이나 일반론 중심이며 근거가 거의 없음 | 8 |
| 성장 루프 | 반복 행동과 가치 증가 구조를 명확히 설명 | 퍼널은 있으나 반복 루프 설명이 약함 | 기능 목록이나 화면 묘사에 머묾 | 7 |
| 실험 가설 | 지표와 판정 기준이 있는 가설 5개 이상 | 가설은 있으나 측정 기준이 일부 없음 | 해결책 아이디어만 나열 | 5 |

### 미션 2: 3종 문서, 25점

| 기준 | 우수 | 보통 | 미흡 | 배점 |
|---|---|---|---|---:|
| 제품 문서 | 고객 문제, 여정, 범위, 지표가 구체적 | 주요 항목은 있으나 범위 또는 검증 기준이 모호 | 기능 요구만 나열 | 8 |
| BM 문서 | 가치 교환, 성장, 수익, 위험이 연결됨 | Canvas는 있으나 검증 가설이 약함 | 수익 아이디어만 제시 | 7 |
| 개발설계 | 사용자 흐름, 데이터, 품질, 테스트가 구현 가능 수준 | 기술 스택과 화면은 있으나 품질·데이터 정의가 부족 | 도구 이름만 나열 | 7 |
| 추적성 | `OBS→PRD→BM→ADR` 연결이 일관됨 | 일부 연결이 누락됨 | 문서가 서로 다른 제품을 설명함 | 3 |

### 미션 3: AI 기반 구현, 30점

| 기준 | 우수 | 보통 | 미흡 | 배점 |
|---|---|---|---|---:|
| 대표 흐름 | 처음부터 완료 피드백까지 안정적으로 동작 | 핵심 흐름은 동작하나 일부 오류 복구가 부족 | 데모용 정적 화면에 머묾 | 10 |
| 문서 일치 | 구현과 테스트가 요구사항 ID에 연결됨 | 주요 기능은 일치하나 변경 근거가 일부 없음 | 문서와 실제 동작이 다름 | 6 |
| 품질 | 반응형, 접근성, 성능, 오류 처리를 검증 | 일부 항목만 검증 | 시각 결과 외 품질 검증이 없음 | 6 |
| 테스트 | 핵심·실패 흐름을 자동 또는 재현 가능한 방식으로 검증 | 정상 흐름 위주로 검증 | 재현 가능한 테스트가 없음 | 4 |
| AI 사용 책임성 | 입력·결과·검증·수정 기록이 구체적 | 사용 기록은 있으나 사람의 검증이 불명확 | 생성 결과를 검증 없이 제출 | 4 |

### 미션 4: 비교와 학습, 20점

| 기준 | 우수 | 보통 | 미흡 | 배점 |
|---|---|---|---|---:|
| 비교 설계 | 동일 과업과 조건으로 원본·구현물을 비교 | 비교는 했으나 조건 통제가 약함 | 서로 다른 기준으로 인상만 비교 | 6 |
| 증거 | 사용자 기록과 측정값이 결론에 연결 | 일부 결론만 근거가 있음 | 근거 없는 자기평가 중심 | 5 |
| 비판적 회고 | 개선·손실·AI 오류를 모두 구체적으로 설명 | 장단점은 있으나 원인 분석이 얕음 | 성공 사례만 소개 | 5 |
| 다음 실험 | 지표와 판정 기준이 있는 우선 실험 3개 | 실험은 있으나 기준이 일부 모호 | 일반적인 개선 의견만 제시 | 4 |

## 4. 감점과 통과 제한

아래 항목은 총점과 별도로 적용합니다.

| 상황 | 처리 |
|---|---|
| 출처 또는 관찰 근거 없이 원본 서비스의 내부 전략·성과를 사실로 단정 | 해당 근거 항목 0점 |
| 원본 브랜드 자산이나 저작물을 무단 복제 | 최대 20점 감점 및 수정 후 재제출 |
| 비공개 데이터 접근, 인증 우회, 이용약관을 위반하는 수집 | 프로젝트 미통과 |
| 실행 불가능한 사이트 제출 | 미션 3 대표 흐름 항목 0점 |
| AI 생성물을 검증 없이 제출하거나 사용 기록 누락 | AI 사용 책임성 항목 0점 |
| 실제 개인정보나 비밀 값 노출 | 프로젝트 미통과 및 즉시 제거 |

### 제출 전 자동 미통과 점검

- [ ] 원본 서비스의 계정·인증을 우회하지 않았다.
- [ ] 비공개 API나 자동 대량 수집을 사용하지 않았다.
- [ ] 원본 로고·이미지·영상·문구·소스 코드를 복제하지 않았다.
- [ ] 실제 이름·이메일·전화번호·위치·결제 정보를 저장하지 않았다.
- [ ] AI가 생성한 주장과 코드를 사람이 검증했다.
- [ ] 사이트가 원본 서비스의 공식 결과물로 오해되지 않도록 이름과 자산을 바꿨다.

## 5. 최종 통과 조건

- 총점 70점 이상
- 네 개 미션을 모두 제출
- 미션 3의 대표 사용자 흐름이 실행 가능
- 윤리·법적 경계의 미통과 사유가 없음
- 각 미션에서 해당 배점의 50% 이상 획득

## 8. 발표 체크리스트

- [ ] 30초 안에 선택 서비스, 사용자, 대표 흐름을 설명한다.
- [ ] 핵심 성장 루프를 하나의 그림으로 보여 준다.
- [ ] 관찰 근거가 3종 문서의 어떤 결정으로 이어졌는지 보여 준다.
- [ ] 사이트에서 대표 사용자 흐름을 직접 시연한다.
- [ ] 원본과 구현물의 차이를 같은 기준으로 비교한다.
- [ ] AI가 만든 오류와 사람이 바꾼 결정을 하나 이상 공개한다.
- [ ] 다음 실험 3개와 성공 판정 기준을 제시한다.
