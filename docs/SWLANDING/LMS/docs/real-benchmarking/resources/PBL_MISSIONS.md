# 리얼 벤치마킹 PBL 학생 안내서

무신사, 유튜브, 당근 중 하나를 선택해 성장 구조를 관찰하고, 문서로 역설계하고, AI로 구현한 뒤 원본과 비교하는 4단계 개인 프로젝트입니다. 교사의 추가 설명 없이도 아래 순서대로 진행할 수 있습니다.

## 최종 목표

> 성공한 서비스의 화면을 흉내 내는 데서 끝나지 않고, 성장을 만드는 사용자 행동을 근거로 설명해 새로운 웹서비스로 구현한다.

## 시작 전에 준비할 것

- Chrome 또는 Edge 브라우저
- 화면 캡처 도구
- Markdown을 편집할 수 있는 에디터
- Git과 Node.js LTS
- 코딩을 도와줄 AI 도구
- 총 16~24시간의 개인 작업 시간

설치가 어렵다면 [미션 3의 환경 점검](MISSION_3_AI_BUILD.md#2-시작-전-환경-점검)부터 확인합니다.

## 진행 순서

| 순서 | 미션 | 권장 시간 | 완료 결과 | 배점 |
|---:|---|---:|---|---:|
| 1 | [성장 구조 벤치마킹](MISSION_1_GROWTH_BENCHMARK.md) | 4~6시간 | 관찰 10건, 성장 루프, 실험 가설 | 25 |
| 2 | [3종 문서 역설계](MISSION_2_DOCUMENTATION.md) | 4~6시간 | 제품·BM·개발설계 문서 | 25 |
| 3 | [AI 기반 사이트 구현](MISSION_3_AI_BUILD.md) | 6~10시간 | 실행 가능한 사이트와 테스트 | 30 |
| 4 | [원본과 결과 비교](MISSION_4_COMPARISON.md) | 3~5시간 | 비교 보고서와 다음 실험 | 20 |

총점과 평가 방법은 [평가 루브릭](EVALUATION_RUBRIC.md)에 있습니다.

## 미션 통과 규칙

미션마다 마지막의 `제출 전 자기점검`을 완료합니다. 통과 조건을 충족하지 못했다면 다음 미션으로 넘어가지 않습니다.

```text
미션 1 근거 OBS-###
  → 미션 2 요구사항 PRD-### / 가설 BM-### / 결정 ADR-###
    → 미션 3 구현 파일 / 테스트 / AI-### 기록
      → 미션 4 비교 근거 CMP-### / 다음 실험 EXP-###
```

## 혼자 진행할 때의 작업 리듬

1. 한 단계의 설명을 읽습니다.
2. 제시된 파일에 직접 기록합니다.
3. AI에게 검토를 요청하되, 사실을 새로 만들지 못하게 제한합니다.
4. 자기점검 표에서 증거 파일 위치를 적습니다.
5. Git을 사용한다면 단계가 끝날 때 커밋합니다.

권장 커밋 예시:

```text
docs: complete mission 1 benchmark evidence
docs: complete product business and engineering specs
feat: implement primary user journey
docs: compare benchmark and implementation
```

## 공통 안전 규칙

- 공개 화면과 공식 공개 자료만 사용합니다.
- 인증 우회, 비공개 API 접근, 대량 자동 수집을 하지 않습니다.
- 원본 소스 코드, 상호, 로고, 문구, 이미지, 영상은 복사하지 않습니다.
- 구현물은 새로운 서비스 이름과 합법적으로 사용할 수 있는 자산을 사용합니다.
- 테스트에 실제 개인정보와 결제 정보를 입력하지 않습니다.
- AI가 말한 내용은 근거가 확인될 때만 사실로 사용합니다.

안전 규칙을 위반하면 점수와 관계없이 미통과할 수 있습니다.

## 막혔을 때

- 무엇을 분석해야 할지 모르겠다면 미션 1의 서비스별 추천 흐름 중 하나를 고릅니다.
- 문서가 너무 커지면 미션 2의 `MVP 범위 자르기` 규칙을 적용합니다.
- 코드가 실행되지 않으면 미션 3의 `고장 해결 순서`를 그대로 따릅니다.
- 비교 기준이 모호하면 미션 4의 공통 과업표를 먼저 작성합니다.
