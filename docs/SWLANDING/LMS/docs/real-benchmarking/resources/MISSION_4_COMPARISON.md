# 미션 4. 원본 서비스와 구현 결과의 차이를 증명하라

## 1. 미션 카드

| 항목 | 내용 |
|---|---|
| 목표 | 원본과 구현물을 같은 과업·조건·기준으로 비교하고 다음 실험을 결정한다 |
| 권장 시간 | 3~5시간 |
| 배점 | 20점 |
| 입력 | 미션 1 기준 자료, 미션 2 문서, 미션 3 사이트와 테스트 기록 |
| 출력 | `COMPARISON.md`, 비교 근거, 다음 실험 3개, 최종 회고 |
| 완료 신호 | 모든 결론에 `CMP-###` 근거가 있고 다음 실험에 판정 기준이 있음 |

이 미션은 “원본과 얼마나 비슷한가”를 평가하지 않습니다. 원본에서 발견한 성장 원리가 새로운 서비스에서 어떻게 유지·변형·손실되었는지 평가합니다.

## 2. 비교 전에 기준선 고정하기

`reports/COMPARISON.md` 첫 부분에 작성합니다.

```markdown
## 비교 기준선
- 원본 서비스:
- 원본 관찰 일시:
- 구현 사이트 버전 또는 커밋:
- 구현 사이트 측정 일시:
- 기기와 브라우저:
- 화면 크기:
- 로그인 상태:
- 공통 대표 과업:
- 비교 제한 사항:
```

원본 서비스는 미션 1 이후 바뀔 수 있습니다. 바뀐 화면은 새 근거로 캡처하고 “기준선 변경”이라고 표시합니다.

## 3. 공통 대표 과업 만들기

두 사이트에서 의미가 같은 시작과 끝을 정의합니다.

```text
시작: 첫 화면을 처음 본 상태
과업: [관심 콘텐츠를 발견하고 신뢰 근거를 확인한다]
끝: [주요 행동 버튼을 선택하거나 완료 상태를 확인한다]
```

원본에서는 구매, 구독, 채팅 직전까지만 수행해도 됩니다. 실제 결제나 타인에게 메시지를 보내지 않습니다.

## 4. 혼자 수행하는 3회 반복 테스트

같은 사람의 반복은 실제 사용자 테스트를 대신하지 못하지만, 절차와 기술 차이를 비교하는 근거가 됩니다.

1. 원본 서비스의 공통 과업을 1회 수행합니다.
2. 브라우저 상태를 초기화하고 구현 사이트에서 수행합니다.
3. 순서를 바꿔 2회 더 반복합니다.
4. 각 실행의 시간, 행동 수, 막힘, 오류를 기록합니다.

| 실행 | 대상 | 완료 | 시간 | 클릭·입력 수 | 막힘 수 | 오류 수 | 메모 |
|---:|---|---|---:|---:|---:|---:|---|
| 1 | 원본 | 예/아니오 |  |  |  |  |  |
| 2 | 구현 | 예/아니오 |  |  |  |  |  |

가능하면 3명의 동료에게 같은 과업을 요청해 별도 기록합니다. 이는 권장 사항이며 혼자 진행하는 학생의 필수 조건은 아닙니다.

## 5. 7개 영역 비교하기

각 판단에 `CMP-001`부터 ID를 붙입니다.

| 영역 | 비교 질문 | 근거 |
|---|---|---|
| 가치 이해 | 첫 화면에서 대상·가치·다음 행동을 이해하는가? | 5초 기록, 제목·CTA 캡처 |
| 과업 효율 | 대표 행동을 얼마나 적은 마찰로 완료하는가? | 시간, 단계, 오류 수 |
| 성장 구조 | 다음 행동·재방문·공유를 만드는 장치가 있는가? | 성장 루프와 화면 연결 |
| 신뢰 | 행동 전 불안을 줄이는 근거가 있는가? | 후기, 정책, 출처, 상태 피드백 |
| BM 연결 | 화면의 행동이 가치 교환·지속 가능성과 연결되는가? | BM-###와 UI 연결 |
| 기술 품질 | 접근성·반응형·성능·복구가 충분한가? | Lighthouse, 빌드, 테스트 |
| 독창성 | 원리를 새 맥락에 맞게 바꿨는가? | ADR과 변경 이유 |

### 비교 기록 형식

```markdown
## CMP-001 — [비교 제목]
- 영역:
- 연결 근거: OBS-___ / PRD-___ / BM-___ / ADR-___
- 원본에서 확인한 내용:
- 구현물에서 확인한 내용:
- 분류: 유지/개선/손실/의도적 변경
- 근거 파일 또는 측정값:
- 차이가 생긴 이유:
- 사용자에게 미치는 영향:
```

최소 10개의 `CMP-###`를 작성합니다.

## 6. 기술 지표를 같은 조건에서 측정하기

Lighthouse를 원본과 구현물에 같은 브라우저·기기 모드로 실행합니다. 로그인이나 개인화 때문에 원본 측정이 불가능하면 그 이유를 적고 비교에서 제외합니다.

| 지표 | 원본 | 구현 | 차이 | 해석 가능 여부 |
|---|---:|---:|---:|---|
| Performance |  |  |  |  |
| Accessibility |  |  |  |  |
| Best Practices |  |  |  |  |
| SEO |  |  |  |  |

[Lighthouse 공식 안내](https://developer.chrome.com/docs/lighthouse)와 [Core Web Vitals 학습 자료](https://web.dev/explore/learn-core-web-vitals)를 기준으로 사용합니다. 서로 다른 네트워크 조건에서 나온 숫자를 단순 비교하지 않습니다.

## 7. 사용성 휴리스틱 점검하기

[Nielsen Norman Group의 10가지 사용성 휴리스틱](https://www.nngroup.com/articles/ten-usability-heuristics/) 중 아래 5개를 필수로 확인합니다.

- 시스템 상태가 보이는가?
- 사용자의 언어와 실제 세계의 개념을 사용하는가?
- 사용자가 취소하거나 이전 상태로 돌아갈 수 있는가?
- 오류를 예방하고 복구 방법을 설명하는가?
- 필요한 도움말이나 안내가 있는가?

각 문제에는 심각도를 붙입니다.

| 심각도 | 의미 |
|---:|---|
| 0 | 문제가 아님 |
| 1 | 외형 수준의 작은 문제 |
| 2 | 일부 사용자를 지연시키는 문제 |
| 3 | 대표 과업을 어렵게 만드는 큰 문제 |
| 4 | 대표 과업을 완료할 수 없는 문제 |

## 8. AI의 판단을 평가하기

`AI_BUILD_LOG.md`에서 최소 3개의 결정을 골라 작성합니다.

| AI 작업 ID | AI가 제안한 것 | 결과 | 사람의 수정 | 배운 점 |
|---|---|---|---|---|
| AI-001 |  | 채택/수정/기각 |  |  |

AI가 잘한 것만 쓰지 않습니다. 사실을 만들었거나 범위를 넓혔거나 접근성을 놓친 사례도 기록합니다.

## 9. 다음 성장 실험 3개 결정하기

```markdown
## EXP-NEXT-001 — [실험 제목]
- 발견 근거: CMP-___
- 대상 사용자:
- 바꿀 한 가지:
- 1차 지표:
- 부작용 확인 지표:
- 성공 기준:
- 실패 기준:
- 가장 작은 구현 범위:
- 우선순위 이유:
```

“디자인 개선”처럼 범위가 넓은 항목은 실험이 아닙니다. 한 번에 한 가지 변화와 한 가지 주요 지표를 둡니다.

## 10. 비교 보고서 작성하기

`reports/COMPARISON.md` 목차:

```markdown
# 원본 서비스와 구현 사이트 비교
## 1. 비교 대상과 기준선
## 2. 공통 대표 과업
## 3. 반복 테스트 결과
## 4. 제품 경험 차이
## 5. 성장 루프 차이
## 6. 비즈니스 모델 차이
## 7. 기술·품질 차이
## 8. 유지·개선·손실·의도적 변경
## 9. AI가 잘한 판단과 사람이 수정한 판단
## 10. 다음 성장 실험 3개
## 11. 한계와 결론
```

## 11. AI로 결론의 과장을 검사하기

```text
아래 비교 보고서에서 근거보다 강하게 말한 결론을 찾아줘.
새로운 사실은 추가하지 말고 다음 기준으로만 검사해줘.

1. 측정 조건이 다른 수치 비교
2. 한 사람의 테스트를 전체 사용자에게 일반화
3. 상관관계를 인과관계로 표현
4. 원본 서비스의 내부 데이터 추측
5. 장점만 있고 손실이나 한계가 없는 결론

각 항목에 문제 문장, 문제 이유, 더 정확한 수정 문장을 제안해줘.
```

수정 후에도 보고서의 한계 항목은 삭제하지 않습니다.

## 13. 제출 전 자기점검

- [ ] 원본과 구현물의 과업과 측정 조건이 같다.
- [ ] 반복 테스트 결과가 표로 남아 있다.
- [ ] `CMP-###` 10건 이상이 근거 파일과 연결된다.
- [ ] 차이를 유지·개선·손실·의도적 변경으로 분류했다.
- [ ] 기술 지표의 측정 조건과 한계를 기록했다.
- [ ] AI의 채택·수정·기각 사례를 모두 포함했다.
- [ ] 다음 실험 3개에 성공·실패 기준이 있다.
- [ ] 원본보다 낫다는 근거 없는 결론을 쓰지 않았다.
