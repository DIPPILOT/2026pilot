# 미션 1. 실제 서비스의 성장 구조를 벤치마킹하라

## 1. 미션 카드

| 항목 | 내용 |
|---|---|
| 목표 | 공개 화면에서 사용자의 다음 행동을 만드는 장치를 찾아 성장 루프로 설명한다 |
| 선택 대상 | 무신사, 유튜브, 당근 중 하나 |
| 권장 시간 | 4~6시간 |
| 배점 | 25점 |
| 입력 | 브라우저에서 직접 관찰한 화면과 공식 공개 자료 |
| 출력 | 프로젝트 폴더, 관찰 10건 이상, 퍼널, 성장 루프, 실험 가설 5건 |
| 완료 신호 | 모든 핵심 주장에 `OBS-###` 근거가 연결됨 |

여기서 그로스 해킹은 시스템에 침입하는 행위가 아닙니다. 사용자가 유입되고, 첫 가치를 경험하고, 다시 방문하거나 다른 사용자를 부르는 구조를 관찰해 실험 가설로 만드는 활동입니다.

## 2. 서비스 하나 선택하기

아래 질문에 가장 답하고 싶은 서비스를 선택합니다.

| 서비스 | 추천 질문 | 추천 대표 흐름 | 공식 시작 링크 |
|---|---|---|---|
| 무신사 | 콘텐츠·리뷰·혜택이 구매 의도에 어떻게 연결되는가? | 상품 발견 → 상세 탐색 → 신뢰 확인 → 구매 의도 | [무신사](https://www.musinsa.com/), [무신사 기업 서비스 소개](https://corp.musinsa.com/ko/business) |
| 유튜브 | 한 편의 영상이 다음 시청과 재방문을 어떻게 만드는가? | 콘텐츠 발견 → 시청 → 다음 영상 → 구독·재방문 | [YouTube](https://www.youtube.com/), [How YouTube Works](https://www.youtube.com/howyoutubeworks/) |
| 당근 | 지역성과 신뢰가 거래 또는 참여 의도를 어떻게 만드는가? | 동네 진입 → 게시물 발견 → 신뢰 확인 → 채팅 의도 | [당근](https://www.daangn.com/), [당근 서비스 소개](https://about.daangn.com/service/) |

선택 문장을 프로젝트 README에 작성합니다.

```markdown
선택 서비스: [서비스명]
대표 사용자: [누가]
대표 과업: [무엇을 완료하려 하는가]
선택 이유: [왜 이 흐름이 성장과 연결된다고 보는가]
관찰 기준일: [YYYY-MM-DD]
```

## 3. 프로젝트 폴더 만들기

`{team-name}`은 개인이면 영문 이름이나 학번 별칭을 사용합니다. `{service-name}`은 `musinsa`, `youtube`, `daangn` 중 하나입니다.

```text
teams/{team-name}/{service-name}/
├── README.md
├── research/
│   ├── BENCHMARK_LOG.md
│   ├── GROWTH_LOOP.md
│   └── evidence/
├── docs/
│   ├── 01-product/OPPORTUNITY.md
│   ├── 02-business/BUSINESS_MODEL.md
│   └── 03-engineering/BASE_ARCHITECTURE.md
├── development/
│   ├── apps/web/
│   ├── packages/ui/src/
│   ├── packages/config/
│   └── tests/e2e/
└── reports/
    ├── AI_BUILD_LOG.md
    └── COMPARISON.md
```

터미널을 사용할 수 있다면 프로젝트 루트에서 실행합니다. 예시 이름은 반드시 자신의 값으로 바꿉니다.

```bash
mkdir -p teams/my-name/musinsa/{research/evidence,docs/01-product,docs/02-business,docs/03-engineering,development/apps/web,development/packages/ui/src,development/packages/config,development/tests/e2e,reports}
```

터미널이 어렵다면 파일 탐색기에서 같은 구조로 폴더와 빈 Markdown 파일을 만듭니다.

## 4. 관찰 규칙 익히기

관찰과 해석을 섞지 않습니다.

- 관찰: “상품 카드에 후기 수와 평점이 함께 표시된다.”
- 해석: “구매 전 불확실성을 줄여 상세 진입을 돕는 것으로 보인다.”
- 잘못된 단정: “후기 표시 때문에 매출이 30% 증가한다.”

화면에 보이지 않는 알고리즘, 매출, 전환율은 공식 출처가 없으면 가설입니다. 유튜브 추천 시스템을 분석한다면 먼저 [YouTube의 공식 추천 설명](https://support.google.com/youtube/answer/16089387)을 읽고, 공식 설명과 자신의 화면 관찰을 구분합니다.

## 5. 관찰 세션 3회 수행하기

한 번에 보지 말고 목적이 다른 세션을 진행합니다.

### 세션 A: 첫 방문, 30분

1. 로그아웃 또는 시크릿 창에서 시작합니다.
2. 첫 화면에서 보이는 가치, 선택지, CTA를 기록합니다.
3. 5초 안에 이해한 내용을 한 문장으로 씁니다.
4. 다음 행동을 유도한 요소를 캡처합니다.

### 세션 B: 대표 과업, 45분

1. 선택한 대표 과업을 시작합니다.
2. 클릭·스크롤·입력 단계 수를 셉니다.
3. 각 단계의 기대, 실제 결과, 망설임을 기록합니다.
4. 신뢰 요소와 이탈 요소를 각각 찾습니다.

### 세션 C: 재방문 장치, 30분

1. 다음 콘텐츠, 알림, 저장, 구독, 리뷰, 공유 장치를 찾습니다.
2. 사용자의 활동이 다른 사용자에게 가치를 만드는 지점을 찾습니다.
3. 재방문이 일어나려면 어떤 조건이 필요한지 가설로 씁니다.

로그인이나 개인정보가 필요한 단계에서는 실제 데이터를 제출하지 않아도 됩니다. 버튼 직전까지 관찰하고 제한 사항을 기록합니다.

## 6. 관찰 로그 10건 작성하기

`research/BENCHMARK_LOG.md`에 아래 형식을 복사해 `OBS-001`부터 작성합니다.

```markdown
## OBS-001 — [짧은 관찰 제목]

- 관찰 일시: YYYY-MM-DD HH:mm
- URL 또는 화면 위치:
- 환경: 모바일/데스크톱, 로그인/비로그인
- 사용자 목표:
- 관찰한 사실:
- 팀의 해석:
- 다음 행동에 미치는 영향:
- AARRR 단계: 획득/활성화/유지/추천/수익
- 근거 파일: research/evidence/OBS-001.png
- 불확실성 또는 추가 확인:
```

파일명은 `OBS-001-home-cta.png`처럼 ID와 내용을 함께 씁니다. 캡처에는 계정명, 이메일, 위치 등 개인정보가 보이지 않게 합니다.

## 7. AARRR 퍼널로 분류하기

| 단계 | 학생이 답할 질문 | 관찰 예시 |
|---|---|---|
| 획득 | 사용자는 어디서 처음 들어오는가? | 검색, 공유 링크, 추천 피드, 캠페인 |
| 활성화 | 첫 번째 가치 경험은 무엇인가? | 원하는 상품·영상·게시물을 발견 |
| 유지 | 다시 돌아올 이유는 무엇인가? | 새 콘텐츠, 알림, 저장 목록, 개인화 |
| 추천 | 다른 사용자를 부르는 행동은 무엇인가? | 공유, 후기, 콘텐츠 등록, 초대 |
| 수익 | 어떤 가치 교환이 수익과 연결되는가? | 거래, 광고, 구독, 판매 수수료 |

`research/GROWTH_LOOP.md`에 각 단계별 `OBS-###`를 연결합니다. 근거가 없는 칸은 억지로 채우지 말고 `미관찰`이라고 씁니다.

## 8. 성장 루프 그리기

다음 문장을 완성한 뒤 화살표로 그립니다.

```text
[사용자 행동]
  → [서비스 안의 가치가 증가]
  → [다른 사용자가 발견하거나 반응]
  → [신규 유입 또는 기존 사용자 재방문]
  → [첫 행동이 더 많이 발생]
```

성장 루프 아래에 반드시 작성합니다.

- 가장 강한 근거 3개: `OBS-___`, `OBS-___`, `OBS-___`
- 아직 보이지 않는 연결:
- 이 루프가 멈추는 조건:
- 새 서비스에 가져올 원리:
- 그대로 복제하면 안 되는 요소:

## 9. 실험 가설 5개 만들기

```markdown
## EXP-001 — [실험명]
- 연결 근거: OBS-___
- 대상 사용자:
- 가설: 만약 [변화]를 제공하면 [이유] 때문에 [지표]가 변할 것이다.
- 1차 지표:
- 부작용 확인 지표:
- 성공 기준:
- 가장 작은 검증 방법:
- 영향도 1~5:
- 근거 수준 1~5:
- 구현 난이도 1~5: # 낮을수록 쉬움
- 우선순위 점수: (영향도 × 근거 수준) ÷ 구현 난이도
```

점수가 가장 높은 실험 하나가 미션 2와 3의 중심이 됩니다.

## 10. AI에게 받을 수 있는 도움

관찰 기록 전체를 주지 않아도 됩니다. 개인정보를 제거한 3~5개 관찰만 입력합니다.

```text
나는 [서비스]의 공개 화면을 관찰했다. 아래 내용에서 사실과 해석을 분리하고,
근거 없이 단정한 문장을 찾아 질문으로 바꿔줘. 새로운 사실은 만들지 마.

[OBS 기록 붙여넣기]

출력 형식:
1. 확인 가능한 사실
2. 해석 또는 가설
3. 근거가 부족한 주장
4. 다음 관찰에서 확인할 질문
```

AI 답변은 관찰 근거가 아닙니다. 채택한 수정만 자신의 문서에 반영합니다.

## 11. 제출물

- 프로젝트 `README.md`
- `research/BENCHMARK_LOG.md`: `OBS-###` 10건 이상
- `research/GROWTH_LOOP.md`: AARRR, 성장 루프, `EXP-###` 5건 이상
- `research/evidence/`: 관찰과 연결된 캡처

## 12. 제출 전 자기점검

- [ ] 서비스, 사용자, 대표 과업이 한 문장으로 정의되었다.
- [ ] 폴더 구조가 요구사항과 일치한다.
- [ ] 10개 이상의 관찰에 날짜·URL·환경이 있다.
- [ ] 사실과 해석을 다른 항목에 적었다.
- [ ] 모든 주요 주장에 `OBS-###`가 연결되었다.
- [ ] 성장 루프에 멈추는 조건까지 적었다.
- [ ] 5개 실험에 지표와 성공 기준이 있다.
- [ ] 개인정보와 원본 저작물을 제출물에 포함하지 않았다.

## 13. 미션 1 채점표, 25점

| 평가 요소 | 배점 | 만점 기준 |
|---|---:|---|
| 폴더와 기록 구조 | 5 | 모든 산출물이 정해진 위치에 있고 README에서 찾을 수 있음 |
| 관찰 근거 | 8 | 10건 이상이며 날짜·URL·환경·캡처가 주장과 연결됨 |
| 성장 퍼널과 루프 | 7 | 반복 행동, 가치 증가, 재유입, 정지 조건을 근거로 설명함 |
| 실험 가설 | 5 | 5개 이상이며 지표·성공 기준·우선순위가 있음 |
