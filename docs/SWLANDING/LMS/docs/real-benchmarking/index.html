MISSION 01 · DISCOVER

실제 서비스의 성장 구조를 관찰하라

공개 화면에서 사용자의 다음 행동을 만드는 장치를 찾아, 관찰 가능한 근거로 성장 루프를 설명합니다.

25POINTS
입력 공개 화면·공식 자료출력 OBS 10+ · EXP 5+완료 신호 주장마다 근거 연결
01

관찰 대상을 고정하세요

서비스 하나, 대표 사용자 한 명, 대표 과업 하나만 선택합니다. 내부 알고리즘이나 매출은 공식 출처가 없으면 사실이 아니라 가설입니다.

무신사상품 발견 → 상세 탐색 → 신뢰 확인 → 구매 의도유튜브콘텐츠 발견 → 시청 → 다음 영상 → 재방문당근동네 진입 → 게시물 발견 → 신뢰 확인 → 채팅 의도
02

3회의 관찰 세션을 수행하세요

  1. 첫 방문 · 30분로그아웃 상태에서 가치, 선택지, CTA와 5초 인상을 기록합니다.
  2. 대표 과업 · 45분클릭·스크롤·입력 수, 기대와 실제 결과, 신뢰·이탈 요소를 기록합니다.
  3. 재방문 장치 · 30분저장·구독·알림·후기·공유가 다음 방문이나 타인의 가치로 이어지는 지점을 찾습니다.
03

근거를 ID로 연결하세요

OBSERVATION TEMPLATE
## OBS-001 — [관찰 제목]\n- 관찰 일시 / URL / 환경:\n- 사용자 목표:\n- 관찰한 사실:\n- 나의 해석:\n- 다음 행동에 미치는 영향:\n- AARRR 단계:\n- 근거 파일:\n- 불확실성:

관찰: “상품 카드에 평점과 후기 수가 표시된다.” / 해석: “상세 진입 전 불확실성을 줄이는 것으로 보인다.” 둘을 섞지 마세요.

04

AARRR을 반복되는 성장 루프로 바꾸세요

사용자 행동→서비스 가치 증가→다른 사용자 반응→유입·재방문

가장 강한 OBS 3개, 보이지 않는 연결, 루프가 멈추는 조건, 가져올 원리와 복제하면 안 되는 요소를 함께 씁니다.

MISSION 02 · DEFINE

관찰 결과를 3종 문서로 역설계하라

미션 1의 근거를 제품 기회, 비즈니스 모델, 개발 기본설계라는 실행 가능한 계약으로 바꿉니다.

25POINTS
입력 OBS · GROWTH LOOP출력 3개 핵심 MD완료 신호 OBS→PRD→BM→ADR
01

근거 추적표부터 만드세요

각 결정이 어디에서 시작됐는지 한 줄로 추적합니다. 문서가 서로 다른 제품을 설명하지 않게 하는 중심 장치입니다.

OBS-001→PRD-001→BM-001→ADR-001
02

3개의 문서를 순서대로 작성하세요

PRODUCTOPPORTUNITY.md문제·여정·PRD·MVP 범위·성공 지표예시 다운로드 →BUSINESSBUSINESS_MODEL.md가치 교환·AARRR·Canvas·BM 가설·위험예시 다운로드 →ENGINEERINGBASE_ARCHITECTURE.md흐름·데이터·이벤트·품질·테스트·ADR예시 다운로드 →
03

MVP는 1개 흐름, 1–3개 화면으로 자르세요

  • 한 번의 방문에서 사용자가 경험할 수 있는가?
  • 최우선 성장 가설을 보여 주는가?
  • 6–10시간 안에 구현하고 테스트할 수 있는가?
  • 실제 개인정보·결제·외부 서비스 없이 데모할 수 있는가?

로그인·결제·실시간 채팅·추천 알고리즘은 목업 데이터로 대체할 수 있습니다.

30POINTS
입력 PRD · BM · ADR출력 WEB · TEST · AI LOG완료 신호 LINT·BUILD 성공
01

환경과 구현 기준선을 먼저 확인하세요

node --version
npm --version
git --version

npx create-next-app@latest development/apps/web

02

3번의 수직 사이클로 완성하세요

  1. 가치 이해5초 안에 대상·가치를 이해하고 CTA를 찾을 수 있게 합니다.
  2. 핵심 행동탐색 또는 입력으로 상태가 바뀌며 로딩·빈 결과·잘못된 입력을 처리합니다.
  3. 완료와 다음 행동완료 피드백과 저장·공유·다음 탐색 등 성장 가설의 다음 행동을 연결합니다.

MISSION 04 · LEARN

원본과 구현 결과의 차이를 증명하라

두 사이트에서 같은 과업과 조건을 사용해 성장 원리가 유지·개선·손실·변형된 지점을 증명합니다.

20POINTS
입력 원본·구현·TEST출력 CMP 10+ · EXP 3완료 신호 결론마다 근거
01

같은 비교 기준선을 고정하세요

원본·구현 버전, 측정 일시, 기기·브라우저·화면 크기·로그인 상태와 공통 과업을 먼저 기록합니다. “비슷한가”가 아니라 “같은 목표를 어떻게 달성하는가”를 비교합니다.

동일 시작→동일 과업→동일 종료→동일 조건
02

순서를 바꾸며 3회 반복하세요

원본과 구현물을 번갈아 수행하고 완료 여부, 시간, 클릭·입력 수, 막힘, 오류를 기록합니다. 혼자 한 테스트는 사용자 전체를 대표하지 않는다는 한계도 씁니다.

가치 이해5초 기록
과업 효율시간·단계·오류
성장 구조다음 행동·재방문
신뢰불안 감소 근거
BM 연결가치 교환
기술 품질접근성·성능
독창성원리의 변형
03

CMP 기록을 판단 근거로 만드세요

COMPARISON TEMPLATE
## CMP-001 — [비교 제목]\n- 영역 / 연결 근거:\n- 원본에서 확인한 내용:\n- 구현물에서 확인한 내용:\n- 분류: 유지/개선/손실/의도적 변경\n- 근거 파일 또는 측정값:\n- 차이가 생긴 이유:\n- 사용자에게 미치는 영향:
04

다음 실험 3개로 프로젝트를 닫으세요

각 `EXP-NEXT-###`에는 발견 근거 CMP, 바꿀 한 가지, 1차·부작용 지표, 성공·실패 기준, 가장 작은 구현 범위와 우선순위 이유가 있어야 합니다.

“디자인 개선”은 실험이 아닙니다. 한 번에 한 가지 변화와 하나의 주요 지표를 둡니다.
