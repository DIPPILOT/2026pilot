📌 5대 기획 문서 구조 가이드

SITE_SPEC.md            # 목적, 사용자, 완료 기준 체크리스트
USER_FLOWS.md           # 학생 & 선생님 단계별 이용 동선
DATA_MODEL.md           # 이름, 출석 시간, 상태 데이터 구조
IMPLEMENTATION_PLAN.md  # 구현 순서 및 테스트 항목
CONVERSATION.md         # 대화 프롬프트 및 결정 이력 기록

💡 코덱스 구현 요청 핵심 프롬프트

"위 5개 기획 문서를 정독하고, website/ 폴더 아래 
1) 학생 출석 카드 선택 및 QR 생성 화면
2) 선생님 출석 현황 실시간 모니터링 화면
을 HTML/CSS/JS로 구현해 줘. 모바일 레이아웃과 예외 처리를 반영해 줘."

🧰 gstack으로 기획 문서 점검하기

Codex로 문서를 작성한 뒤 gstack 스킬로 문서를 검토합니다. 결과는 그대로 채택하지 말고 팀이 판단한 내용만 문서에 반영하고 CONVERSATION.md에 기록합니다.

/office-hours        → PROJECT_BRIEF.md   문제·사용자·범위 점검 (기획 전)
/plan-ceo-review     → SITE_SPEC.md       범위 점검 (Hold Scope / Reduction 모드)
/plan-eng-review     → USER_FLOWS.md      예외 흐름 · 숨은 가정
                       DATA_MODEL.md      데이터 흐름 · 필드 · 관계
                       IMPLEMENTATION_PLAN.md  구현 순서 · 테스트 계획
/autoplan (선택)      → 위 리뷰를 한 번에 실행, 사람이 결정할 항목만 정리
/document-release    → 구현 완료 후 문서를 최종 코드에 맞게 업데이트
(모든 결과 요약)      → CONVERSATION.md
"/plan-eng-review
