PATH A Windows 네이티브 설치 - 초급자 기본 과정

  1. PowerShell 열기

    키보드의 Windows 키를 누르고 PowerShell을 검색한 뒤 실행합니다. 창에 PS C:\Users\사용자이름>이 보이면 정상입니다.

  2. Git과 Node.js 설치

    아래 명령을 한 줄씩 붙여넣고 Enter를 누릅니다.

    winget install --id Git.Git -e winget install OpenJS.NodeJS.LTS

    예상 결과 · 설치 완료 메시지가 나온 뒤 PowerShell을 닫고 다시 엽니다.

  3. Bun 설치

    powershell -c "irm bun.sh/install.ps1|iex"

    PowerShell을 새로 열고 bun --version을 입력했을 때 숫자가 나오면 성공입니다.

  4. Codex 설치와 로그인

    powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
    codex --version codex

    처음 실행하면 화면 안내에 따라 ChatGPT 계정 등의 제공되는 방식으로 로그인합니다.

  5. Claude Code 설치와 로그인

    winget install Anthropic.ClaudeCode
    claude --version claude doctor claude

    Claude Code 사용이 가능한 계정이 필요합니다. 한 도구만 사용할 경우 이 단계는 건너뛰어도 됩니다.

  6. 설치 결과 한 번에 확인

    git --version node --version npm --version bun --version codex --version claude --version

    각 줄에 버전 번호가 표시되면 다음 단계로 이동합니다.

  7. gstack 내려받기

    git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git "$HOME\gstack" cd "$HOME\gstack"

  8. gstack을 Codex·Claude Code에 등록

    .\setup.ps1 --host codex .\setup.ps1 --host claude .\setup.ps1 --status

    한 도구만 사용한다면 해당 host 명령만 실행합니다. 상태 표에 codex 또는 claude가 나오면 성공입니다.

  9. ZIP 실습 폴더에서 PowerShell 열기

    ZIP을 마우스 오른쪽 버튼으로 눌러 모두 추출합니다. 압축을 푼 project 폴더를 열고, 탐색기 주소 표시줄에 powershell을 입력한 뒤 Enter를 누릅니다.

    git init git add . git commit -m "실습 시작 상태" git status

  10. 첫 실습 시작

    AI 작업 전후에는 반드시 git status와 git diff를 확인합니다.

PATH B WSL2 Ubuntu 설치 - 선택 과정

WSL은 무엇인가요?

WSL은 Windows Subsystem for Linux의 약자입니다. Windows 안에서 Ubuntu 터미널과 Linux 개발 도구를 실행할 수 있게 합니다. gstack을 사용하기 위한 필수 조건은 아닙니다.

  1. 관리자 PowerShell에서 WSL 설치

    wsl --install

    설치가 끝나면 컴퓨터를 재부팅합니다.

  2. Ubuntu 첫 실행

    시작 메뉴에서 Ubuntu를 실행하고 Linux 사용자 이름과 비밀번호를 만듭니다. 비밀번호 입력 중 문자가 보이지 않는 것은 정상입니다.

  3. Ubuntu에서 필수 도구 설치

    sudo apt update sudo apt install -y git curl unzip curl -fsSL https://bun.com/install | bash source ~/.bashrc

  4. Codex와 Claude Code를 Ubuntu 안에 설치

    curl -fsSL https://chatgpt.com/codex/install.sh | sh curl -fsSL https://claude.ai/install.sh | bash

  5. gstack도 Ubuntu 안에 설치

    git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/gstack cd ~/gstack ./setup --host codex ./setup --host claude ./setup --status
환경을 섞지 마세요

Codex만 Windows에 설치하고 gstack은 WSL에 설치하면 서로 다른 홈 폴더를 사용합니다. 모두 Windows에 설치하거나 모두 WSL2 Ubuntu에 설치하세요.

막혔을 때 먼저 확인하기

명령을 찾을 수 없음

PowerShell을 완전히 닫고 새로 연 뒤 다시 실행합니다.

setup.ps1 실행 차단

powershell -ExecutionPolicy Bypass -File .\setup.ps1 --host codex처럼 실행합니다.

Git 커밋 이름 오류

git config user.name "student"와 로컬 이메일을 설정합니다.

gstack 스킬이 안 보임

Codex·Claude를 종료하고 새 세션을 연 뒤 .\setup.ps1 --status를 확인합니다.

Bun이 인식되지 않음

PowerShell을 새로 열고 bun --version을 다시 확인합니다.

Windows 보안 기능이 차단

보안 설정을 끄지 말고 강사에게 알린 뒤 WSL2 과정으로 전환합니다.

04개발

BUILD · 여기서부터 수정 허용

계획을 작은 변경으로 나누어 구현

구현은 기본 에이전트 기능으로 수행합니다. 한 기능씩 요청하고, 각 변경 뒤 실행 결과와 Git diff를 확인합니다. gstack은 구현 전후의 계획·검증 역할을 강화합니다.

구현 요청
승인한 명세와 기술 계획을 기준으로
먼저 빈 입력 방지만 구현해 줘.
검증을 수행하고 다른 기능은 건드리지 마.
Git 체크포인트
git status
git diff
git add .
git commit -m "feat: prevent blank tasks"
산출물작은 diff · 실행 결과 · 기능별 커밋통과 조건명세 밖 변경이 없고, 사람이 앱에서 기능을 재현했다.
EXAMPLE OUTPUT 04구현 후 Git·브라우저 확인 예시
$ git diff --stat
app.js | 12 ++++++++++--
1 file changed, 10 insertions(+), 2 deletions(-)

$ git status --short
M app.js

브라우저 확인
✓ 공백 입력: 항목 0개 유지, 안내 표시
✓ 정상 입력: 항목 1개 추가
✓ 기존 완료 버튼: 정상 동작

사람의 확인 → 계획에 없던 파일이 바뀌지 않았고, 정상 흐름도 그대로 동작하는가?

05리뷰·디버깅

REVIEW & DEBUG

변경 위험을 찾고, 증상보다 원인을 고침

review는 diff의 버그·누락·구조적 위험을 찾고, investigate는 재현 → 증거 → 가설 → 수정 순서로 원인을 좁힙니다. 보고만 받을 때는 “수정하지 마”를 명시합니다.

리뷰
gstack-review 스킬로 현재 diff를 검토해 줘.
심각도, 파일 근거, 재현 방법만 보고하고 수정하지 마.

Claude: /review
원인 조사
gstack-investigate 스킬로 중복 항목 원인을 조사해 줘.
재현과 근거를 먼저 제시하고 승인 전에는 수정하지 마.

Claude: /investigate
산출물심각도별 리뷰 · 재현 절차 · 근본 원인통과 조건지적마다 파일/행동 근거가 있고 추측과 사실이 구분된다.
EXAMPLE OUTPUT 05review·investigate 결과 예시
P1 · 사용자 입력이 HTML로 실행될 수 있음

app.js에서 제목을 innerHTML로 삽입한다. 악성 HTML 입력으로 재현 가능하며 텍스트 노드 또는 textContent 사용이 필요하다.

근본 원인

중복 검사를 렌더링 후 수행해 빠른 두 번째 클릭이 같은 배열 상태를 읽는다. 버튼 비활성화가 아니라 검증 순서가 원인이다.

사람의 확인 → 심각도, 파일 위치, 재현 조건, 사용자 영향이 하나의 근거로 연결되는가?

Claude: /qa-only

EXAMPLE OUTPUT 06qa-only 보고서 예시

EXAMPLE OUTPUT 07출시 준비 결과 예시

사람의 확인 → 측정값이나 파일 근거 없이 “안전함·빠름”이라고만 결론 내리지 않았는가?
