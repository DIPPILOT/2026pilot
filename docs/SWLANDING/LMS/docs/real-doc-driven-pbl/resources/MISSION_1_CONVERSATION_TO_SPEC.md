# 미션 1 — 대화를 프로젝트 요구사항으로 재구성하기

## 목표

지금까지의 대화를 그대로 복사하는 것이 아니라, 프로젝트를 시작할 수 있는 요구사항과 결정으로 바꿉니다.

## 학생이 먼저 할 일

Codex를 사용하기 전에 다음을 자신의 언어로 작성합니다.

1. 누구의 어떤 문제를 해결하는가?
2. 고객이 반드시 끝낼 수 있어야 하는 행동은 무엇인가?
3. 관리자가 확인하고 바꿔야 하는 정보는 무엇인가?
4. 이번 MVP에서 하지 않을 것은 무엇인가?
5. 아직 모르거나 확인해야 할 질문은 무엇인가?

## 대화 분류표

| ID | 대화 내용 요약 | 분류 | 근거 | 후속 조치 |
|---|---|---|---|---|
| CONV-001 | 휴대폰으로 주문 | 사실 | 사용자 대화 | 고객 화면 요구사항으로 변환 |
| CONV-002 | 서브웨이와 비슷한 느낌 | 가정 포함 | 사용자 대화 | 복제 금지, 디자인 원리 재정의 |
| CONV-003 | 결제 방식 | 질문 | 대화에 없음 | MVP는 가상 결제로 결정 여부 확인 |

분류는 사실, 가정, 질문, 결정 중 하나로 표시합니다.

## PROJECT_BRIEF.md 필수 항목

- 프로젝트 한 문장
- 대상 사용자와 상황
- 해결할 문제
- 고객 대표 흐름
- 관리자 대표 흐름
- MVP 포함 범위
- MVP 제외 범위
- 성공 기준
- 실패 조건
- 알려진 가정
- 미확정 질문
- 안전·저작권·개인정보 경계

## Codex 요청 예시

```text
다음 대화를 서비스 명세 초안으로 구조화해줘.
대화에 없는 사실을 만들지 말고 각 항목을 사실, 가정, 질문, 결정으로 표시해줘.
고객 모바일 주문과 PC 관리자 요구사항을 분리하고 누락된 예외, 데이터,
검증 질문을 중요도와 함께 제안해줘.
```

## 통과 게이트

- 학생 초안이 AI 응답보다 먼저 존재한다.
- 사실, 가정, 질문, 결정이 혼합되지 않는다.
- 모바일 고객과 PC 관리자의 요구사항이 분리되어 있다.
- MVP 포함·제외 범위가 명확하다.
- 성공 기준과 실패 조건을 관찰할 수 있다.
- 학생이 프로젝트를 1분 안에 자신의 말로 설명할 수 있다.
