02

세 개의 수직 사이클(Vertical Slice)로 완성하세요

  1. Cycle 1 · 고객 모바일 흐름 메뉴 탐색 → 상세·옵션 선택 → 장바구니 담기·수량 조절 → 주문 완료 및 접수 번호 확인 (모바일 360px~430px 기준)
  2. Cycle 2 · 관리자 PC 흐름 실시간 신규 주문 알림·목록 확인 → 주문 상세 조회 → 상태 변경(접수→조리중→픽업대기→완료) → 품절·메뉴 관리 (PC 1280px+ 기준)
  3. Cycle 3 · 예외 및 복구 흐름 필수 옵션 미선택 안내, 품절 메뉴 선택 차단, 빈 장바구니 주문 방지, 네트워크/저장 실패 시 재시도 복구 처리
03

실제 구현된 통합 데모 서비스를 실행해 비교·확인하세요

본 워크스페이스에는 문서 계약과 Fresh Route 디자인 컨셉을 반영해 구현된 고객 모바일 + PC 관리자 실시간 연동 서비스가 포함되어 있습니다.

🚀 모바일+PC 통합 런처 실행 ↗ 📱 고객 모바일 화면 단독 열기 ↗ 🖥️ PC 관리자 화면 단독 열기 ↗

설계와 서비스를 서로 다른 기준으로 검증하라

문서의 완전성(설계 검증)과 실제 앱의 동작·사용성(서비스 검증)을 분리해 검사하고, 발견된 차이를 결함 기록과 학습 회고로 남깁니다.

01

설계 검증(Design Validation)은 문서 간 정합성을 검사합니다

  • 용어, 요구사항 ID, 주문 상태값, 데이터 필드명이 모든 문서에서 일치하는가?
  • 모든 핵심 요구사항에 관찰 가능한 수용 기준(Acceptance Criteria)과 테스트 시나리오가 연결되어 있는가?
  • 고객 모바일의 주문 생성부터 PC 관리자의 상태 변경까지 데이터 흐름이 끊기지 않는가?
  • 권한 경계, 개인정보 제외 규칙, 예외/실패 처리 조건이 누락되지 않았는가?
02

서비스 검증(Service Validation)은 실제 실행 증거를 확인합니다

  • 모바일(360px~430px)과 PC(1280px+) 해상도에서 대표 사용자 흐름을 실제로 재현하고 캡처·기록한다.
  • 정상 주문뿐만 아니라 빈 장바구니, 필수 옵션 미선택, 품절 상품 차단, 취소/거절 상태를 테스트한다.
  • 기본 가격 + 옵션 추가금 × 수량 = 최종 결제 금액 및 주문 상태 변경 결과가 양쪽 화면에서 일치하는지 확인한다.
  • 키보드 탐색, 버튼 레이블, 색상 대비(Fresh Route 접근성), 로딩/토스트 피드백을 점검한다.
