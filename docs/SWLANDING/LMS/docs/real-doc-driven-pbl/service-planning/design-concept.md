# 샌드위치·음료 주문 서비스 디자인 콘셉트

## 1. 문서 목적

이 문서는 모바일 고객 주문 화면과 PC 관리자 화면에 공통으로 적용할 디자인 방향을 정의합니다. 참고 사이트의 인상을 그대로 복제하지 않고, 음식의 신선함과 빠른 주문 경험이라는 핵심만 재해석해 독자적인 화면 체계를 만듭니다.

- 참고 사이트: [Subway Korea](https://www.subway.co.kr/)
- 적용 대상: 고객용 모바일 웹, 매장용 PC 관리자 웹
- 콘셉트 이름: **Fresh Route**
- 핵심 문장: **신선한 메뉴가 먼저 보이고, 다음 행동이 바로 이해되는 주문 경험**

## 2. 참고 사이트에서 가져올 원칙

### 가져올 요소

- 초록과 노랑을 사용한 식품 브랜드 특유의 생동감
- 상품 사진을 크게 보여 주는 음식 중심 구성
- 흰 배경과 넉넉한 여백을 사용한 명확한 정보 구분
- 굵고 짧은 제목과 단순한 카테고리 탐색
- 원형 또는 둥근 모서리의 포인트 그래픽
- 중요한 행동을 색이 분명한 버튼으로 강조하는 방식

### 그대로 복제하지 않을 요소

- 로고, 화살표 모티프, 고유한 브랜드 색상값과 그래픽 형태
- 프로모션 배너 중심의 메인 화면 구성
- 장식 목적으로 사용되는 과도한 슬라이드와 캐러셀
- 주문 과정에서 고객의 선택을 방해하는 마케팅 콘텐츠

### 우리 서비스의 차별점

- 고객 화면은 광고보다 주문 완료 속도를 우선합니다.
- 관리자 화면은 브랜드 표현보다 실시간 주문 판독성을 우선합니다.
- 고객과 관리자가 같은 주문 상태와 색상 체계를 공유합니다.
- 음식 사진은 크게 사용하되 가격, 품절, 필수 옵션이 사진에 묻히지 않게 합니다.

## 3. 디자인 방향

### 미학

- **방향:** Organic & Bold
- **장식 수준:** 의도적이고 절제된 장식
- **느낌:** 신선함, 친근함, 빠름, 정돈됨
- **형태:** 잎, 씨앗, 빵의 곡선을 연상시키는 둥근 모서리와 비대칭 포인트 도형
- **사진:** 밝은 자연광, 실제 식재료 질감, 45도 또는 정면 촬영, 과도한 합성 배경 금지

### 안전한 선택

- 음식 사진과 가격을 메뉴 카드의 가장 중요한 정보로 둡니다.
- 초록색은 주문 진행과 정상 상태에 사용합니다.
- 노란색은 선택, 추천, 강조에 제한적으로 사용합니다.
- 흰색과 따뜻한 회색을 넓게 사용해 복잡도를 낮춥니다.

### 의도적인 차별화

- 흔한 완전 원형 카드 대신, 한쪽 모서리만 크게 둥근 **컷 코너 카드**를 사용합니다.
- 고객 화면의 진행 단계를 **재료가 쌓이는 순서**처럼 시각화합니다.
- 관리자 화면은 같은 브랜드 색을 사용하되 채도를 낮춰 장시간 사용해도 피로하지 않게 합니다.

## 4. 색상 체계

Subway의 초록·노랑 대비에서 영감을 받되 동일한 색상값을 사용하지 않습니다.

### 색상 사용 비율

- 중립색과 흰색: 70%
- 초록색: 20%
- 노랑·주황 및 상태색: 10%
- 한 화면에서 강한 강조색은 최대 두 종류만 사용합니다.
- 색상만으로 상태를 전달하지 않고 아이콘과 문구를 함께 사용합니다.

## 5. 타이포그래피

### 글꼴

- **Display/제목:** `Gmarket Sans` Bold
- **본문/UI:** `Pretendard` Regular, Medium, SemiBold
- **주문번호·금액·표 데이터:** `IBM Plex Mono` 또는 `Pretendard`의 고정폭 숫자 기능
- **대체 글꼴:** `Noto Sans KR`, sans-serif

### 역할별 크기

| 역할 | 모바일 | PC 관리자 | 굵기 |
|---|---:|---:|---:|
| Display | 32px | 40px | 700 |
| 화면 제목 | 24px | 28px | 700 |
| 섹션 제목 | 20px | 22px | 700 |
| 카드 제목 | 17px | 18px | 600 |
| 본문 | 15px | 15px | 400 |
| 버튼 | 16px | 14px | 600 |
| 보조 문구 | 13px | 13px | 400 |
| 주문번호 | 28px | 20px | 700 |

### 원칙

- 제목은 짧고 단단하게 작성합니다.
- 가격은 상품명과 경쟁하지 않되 한눈에 찾을 수 있게 굵게 표시합니다.
- 관리자 표의 숫자는 오른쪽 정렬하고 자릿수 폭을 고정합니다.
- 본문 줄 높이는 1.5 이상, 버튼 줄 높이는 1.2 이상으로 설정합니다.

## 6. 간격과 형태

### 간격 체계

- 기본 단위: 4px
- 간격 단계: `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px`
- 모바일 화면 좌우 여백: 16px
- PC 관리자 본문 여백: 24~32px
- 카드 내부 여백: 모바일 16px, PC 20px

### 모서리

- 작은 요소: 6px
- 버튼과 입력창: 10px
- 일반 카드: 14px
- 대표 메뉴 카드: 좌상단 14px, 우상단 14px, 우하단 32px, 좌하단 14px
- 알약형은 카테고리 탭, 상태 배지, 수량 표시에서만 사용합니다.

### 테두리와 그림자

- 기본 카드: `1px solid #E6E1D5`
- 떠 있는 요소: `0 8px 24px rgba(32, 38, 32, 0.10)`
- 선택 상태는 그림자보다 2px 초록 테두리를 우선합니다.
- 관리자 표에는 그림자를 사용하지 않고 구분선과 배경색으로 행을 구분합니다.

## 7. 고객 모바일 화면 적용

### 레이아웃

- 최소 지원 너비: 360px
- 화면 상단: 매장명, 화면 제목, 장바구니
- 본문: 한 화면에 하나의 의사결정이 중심이 되도록 구성
- 화면 하단: 금액과 주 행동 버튼을 고정
- 메뉴 목록: 2열 카드, 긴 메뉴명은 최대 두 줄

### 시작 화면

- 전체 화면 광고 대신 매장명과 주문 가능 상태를 먼저 표시합니다.
- 대표 샌드위치 사진을 화면 상단의 35~40% 영역에 배치합니다.
- 식사 방식은 사진 아래에서 큰 선택 카드로 제공합니다.
- 주문 시작 버튼은 Fresh Green 단색으로 고정합니다.

### 메뉴 목록

- 상단 카테고리 탭은 스크롤 중에도 유지합니다.
- 메뉴 카드는 사진, 이름, 가격, 배지 순서로 읽히게 합니다.
- 추천 메뉴에는 Harvest Yellow 배지를 사용합니다.
- 품절 메뉴는 사진 채도를 낮추고 `품절` 문구를 이미지 위에 표시합니다.

### 메뉴 상세와 옵션

- 상품 사진과 이름을 먼저 보여 주고 옵션 선택은 아래에서 단계별로 진행합니다.
- 필수 옵션 제목에 `필수` 배지를 붙입니다.
- 선택된 옵션은 연한 초록 배경과 체크 아이콘으로 표시합니다.
- 추가 금액은 옵션 이름 오른쪽에 정렬합니다.

### 장바구니와 결제

- 주문 상품은 세로 목록으로 표시하고 수정과 삭제를 분리합니다.
- 총 금액은 가장 마지막에 큰 숫자로 강조합니다.
- 결제 처리 중에는 버튼 문구를 `결제 확인 중`으로 바꾸고 중복 입력을 막습니다.
- 완료 화면은 주문번호를 가장 크게 보여 주고 장식은 최소화합니다.

### 고객용 주요 컴포넌트

- 카테고리 탭
- 메뉴 카드
- 추천·신메뉴·품절 배지
- 옵션 선택 행
- 수량 조절기
- 하단 고정 주문 바
- 주문 진행 단계
- 결제·네트워크 상태 안내

## 8. PC 관리자 화면 적용

### 레이아웃

- 최소 권장 너비: 1280px
- 좌측 고정 내비게이션: 224px
- 상단 상태 바: 64px
- 본문: 12열 그리드
- 주문 관리: 목록 5열, 상세 7열 비율
- 최대 콘텐츠 너비를 제한하지 않고 화면 폭을 데이터 표시에 활용합니다.

### 관리자 색상 사용

- 좌측 내비게이션에는 Forest Green을 사용합니다.
- 작업 영역은 흰색과 밝은 회색을 중심으로 구성합니다.
- Harvest Yellow는 신규 주문이나 확인 필요 항목에만 사용합니다.
- 위험한 상태에는 초록이나 노랑을 사용하지 않습니다.

### 대시보드

- 첫 행에는 신규 주문, 준비 중, 준비 완료, 지연 주문을 표시합니다.
- 숫자는 크고 문구는 짧게 구성합니다.
- 긴급 알림은 상태색을 사용한 왼쪽 테두리로 구분합니다.
- 매출 그래프보다 현재 처리해야 할 주문을 먼저 배치합니다.

### 주문 관리

- 주문번호, 경과 시간, 상태가 목록의 시각적 기준이 됩니다.
- 선택된 주문 행은 연한 초록 배경으로 표시합니다.
- 15분 이상 지연된 주문은 주황색 시간 배지를 표시합니다.
- 상태 변경 버튼은 현재 가능한 다음 단계만 강조합니다.

### 메뉴와 품절 관리

- 고객 화면에서 보이는 메뉴 사진을 함께 표시합니다.
- 판매 중, 숨김, 품절 상태를 텍스트와 배지로 구분합니다.
- 품절 처리 버튼은 즉시 실행하지 않고 대상과 영향 범위를 확인합니다.
- 저장 완료 후 변경된 고객 화면의 결과를 요약해서 보여 줍니다.

### 관리자용 주요 컴포넌트

- 좌측 내비게이션
- 주문 상태 요약 카드
- 데이터 테이블
- 검색과 필터 바
- 주문 상세 패널
- 상태 배지
- 확인 모달
- 토스트 알림
- 변경 이력 타임라인

## 9. 아이콘과 이미지

### 아이콘

- 2px 선 두께의 단순한 라인 아이콘을 사용합니다.
- 상태 아이콘은 채워진 형태를 사용해 빠르게 구분합니다.
- 장식용 이모지는 실제 서비스 화면에서 사용하지 않습니다.
- 아이콘 버튼에는 항상 접근 가능한 텍스트 이름을 제공합니다.

### 음식 사진

- 배경은 흰색 또는 따뜻한 크림색으로 통일합니다.
- 샌드위치 단면과 재료의 질감이 선명하게 보여야 합니다.
- 메뉴 목록의 이미지 비율은 4:3으로 통일합니다.
- 실제 제공 상품과 다른 과도한 연출 이미지는 사용하지 않습니다.

## 10. 모션

- 모션 방향: 최소 기능 중심
- 버튼과 선택 상태: 120~160ms
- 화면 전환과 패널 열기: 180~240ms
- 주문 상태 변경: 240~320ms
- 진입은 `ease-out`, 종료는 `ease-in`, 위치 이동은 `ease-in-out`을 사용합니다.
- 결제 처리, 주문 접수, 저장 중에는 진행 상태를 보여 주되 반복적으로 튀는 애니메이션은 사용하지 않습니다.
- `prefers-reduced-motion` 설정에서는 이동 효과를 제거합니다.

## 11. 문구 스타일

- 짧고 직접적인 동사를 사용합니다: `주문 시작`, `장바구니 담기`, `결제하기`, `주문 접수`.
- 오류는 문제와 해결 방법을 함께 설명합니다.
- 고객 화면에서는 내부 시스템 용어를 사용하지 않습니다.
- 관리자 화면에서는 상태명을 공통 정책 문서와 동일하게 사용합니다.

### 예시

- 좋은 예: `빵 종류를 선택해 주세요.`
- 피할 예: `필수 옵션값이 누락되었습니다.`
- 좋은 예: `결제 결과를 확인하고 있어요. 버튼을 다시 누르지 마세요.`
- 피할 예: `Payment pending` 또는 `오류 코드 P-102`

## 12. 접근성 기준

- 일반 텍스트는 배경과 최소 4.5:1 대비를 확보합니다.
- 큰 텍스트와 UI 경계는 최소 3:1 대비를 확보합니다.
- 모바일 터치 영역은 최소 44×44px로 설정합니다.
- 키보드 초점은 2px 이상의 명확한 외곽선으로 표시합니다.
- 버튼의 비활성 이유와 입력 오류를 화면 읽기 도구가 읽을 수 있게 연결합니다.
- 모든 음식 이미지에 메뉴명 중심의 대체 텍스트를 제공합니다.
