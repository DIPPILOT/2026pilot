# 모바일 주문 화면 구성

## 화면 설계 원칙

- 모바일 세로 화면을 우선으로 설계합니다.
- 주요 버튼은 화면 하단의 엄지손가락 접근 범위에 배치합니다.
- 가격, 선택한 옵션, 총 주문 금액을 결제 전까지 명확하게 표시합니다.
- 품절, 필수 선택, 결제 실패 상태를 색상만으로 구분하지 않고 문구와 아이콘을 함께 사용합니다.
- 결제처럼 중요한 동작은 중복 실행을 막고 처리 중 상태를 표시합니다.

## 공통 화면 영역

### 상단 영역

- 매장명
- 현재 화면 제목
- 이전 화면 버튼
- 장바구니 버튼과 담긴 상품 수

### 하단 고정 영역

- 현재 주문 금액
- 다음 단계 버튼 또는 장바구니 담기 버튼
- 버튼을 누를 수 없는 경우 그 이유

## 1. 접속 및 주문 시작 화면

### 목적

고객이 접속한 매장과 주문 가능 여부를 확인하고 주문을 시작합니다.

### 표시 내용

- 매장명과 매장 이미지
- 주문 가능 여부
- 주문 가능 시간
- 예상 준비 시간
- 매장 식사 또는 포장 선택
- 주문 시작 버튼

### 확인 및 예외 상태

- 영업시간 종료
- 일시적인 주문 중지
- 유효하지 않은 매장 링크
- 네트워크 연결 실패

## 2. 메뉴 목록 화면

### 목적

고객이 샌드위치와 음료를 탐색하고 원하는 메뉴를 선택합니다.

### 표시 내용

- 카테고리 탭: 추천, 샌드위치, 음료
- 메뉴 이미지, 이름, 짧은 설명, 기본 가격
- 인기 또는 신메뉴 표시
- 품절 상태
- 장바구니 요약과 현재 총액

### 주요 동작

- 카테고리 이동
- 메뉴 상세 열기
- 장바구니 열기
- 메뉴 검색은 추후 범위로 둡니다.

## 3. 메뉴 상세 및 옵션 선택 화면

### 목적

선택한 메뉴의 상세 정보와 필수·선택 옵션을 정합니다.

### 표시 내용

- 메뉴 이미지, 이름, 설명, 기본 가격
- 알레르기 및 원재료 안내 영역
- 필수 옵션과 선택 가능 개수
- 선택 옵션과 추가 금액
- 수량
- 옵션을 반영한 상품 금액

### 샌드위치 옵션

- 빵 종류
- 사이즈
- 추가 재료
- 제외 재료
- 세트 선택

### 음료 옵션

- 사이즈
- 온도
- 얼음 양
- 당도

### 유효성 확인

- 필수 옵션을 선택하지 않으면 장바구니 담기 버튼을 비활성화합니다.
- 선택 가능 개수를 초과하면 원인과 수정 방법을 안내합니다.
- 선택 중 품절된 옵션은 즉시 알리고 대체 선택을 요청합니다.

## 4. 장바구니 화면

### 목적

고객이 결제 전에 선택한 상품과 금액을 검토하고 수정합니다.

### 표시 내용

- 상품별 이름, 옵션, 수량, 금액
- 상품 수정 및 삭제 버튼
- 상품 금액 합계
- 할인 금액 영역
- 최종 결제 예정 금액
- 메뉴 더 담기 버튼
- 주문 확인 버튼

### 확인 및 예외 상태

- 빈 장바구니
- 담은 뒤 품절되거나 가격이 변경된 상품
- 최소 또는 최대 주문 수량 위반

## 5. 주문 확인 화면

### 목적

주문 방식과 주문 내용을 최종 확인한 뒤 결제로 이동합니다.

### 표시 내용

- 매장명
- 매장 식사 또는 포장 여부
- 전체 주문 상품과 옵션
- 요청사항 입력란
- 총 결제 금액
- 주문 변경 버튼
- 결제하기 버튼

### 확인 항목

- 고객이 주문 매장을 잘못 선택하지 않았는지 확인할 수 있어야 합니다.
- 요청사항에는 알레르기 대응을 보장하지 않는다는 안내를 표시합니다.

## 6. 결제 화면

### 목적

고객이 결제 수단을 선택하고 안전하게 결제를 완료합니다.

### 표시 내용

- 최종 결제 금액
- 지원 결제 수단
- 결제 진행 상태
- 결제 취소 또는 이전 화면 이동 조건

### 상태

- 결제 대기
- 결제 처리 중
- 결제 성공
- 결제 실패 및 재시도
- 결제 결과 확인 중

### 처리 원칙

- 결제 처리 중에는 결제 버튼을 다시 누를 수 없게 합니다.
- 결제 결과가 불확실하면 중복 결제를 막고 결과 확인 화면을 먼저 표시합니다.
- 실패 사유를 고객이 이해할 수 있는 문장으로 안내합니다.

## 7. 주문 완료 화면

### 목적

결제와 주문 접수가 완료되었음을 고객에게 확실히 알립니다.

### 표시 내용

- 주문 완료 메시지
- 크게 표시한 주문번호
- 주문 일시와 매장명
- 주문 상품 요약과 결제 금액
- 예상 준비 시간
- 주문 상태 확인 버튼
- 문의 방법

## 8. 주문 상태 화면

### 목적

고객이 별도의 앱 설치 없이 준비 진행 상황을 확인합니다.

### 표시 내용

- 주문번호
- 현재 주문 상태
- 결제 완료, 접수, 준비 중, 준비 완료 단계
- 주문 상품 요약
- 매장 문의 정보

### 상태별 안내

- 접수: 매장에서 주문을 확인 중입니다.
- 준비 중: 상품을 만들고 있습니다.
- 준비 완료: 주문번호를 확인하고 상품을 수령합니다.
- 취소: 취소 사유와 환불 처리 상태를 확인합니다.

## 반응형 및 접근성 기준

- 최소 360px 너비에서 가로 스크롤 없이 사용할 수 있어야 합니다.
- 본문과 버튼은 확대해도 주요 정보가 겹치지 않아야 합니다.
- 터치 영역은 서로 너무 가깝지 않게 배치합니다.
- 입력 오류가 난 항목으로 초점을 이동하고 오류 문구를 함께 제공합니다.
- 화면을 새로 열어도 결제 완료 주문을 다시 확인할 수 있는 진입 방법을 제공합니다.

## 추후 결정 사항

- 회원 주문과 비회원 주문의 구분
- 휴대전화 번호 입력 여부
- 주문 상태 알림 방식
- 모바일 영수증 제공 방식
- 지원할 간편결제 수단
