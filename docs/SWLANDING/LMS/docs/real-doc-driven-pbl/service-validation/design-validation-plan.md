# 디자인 검증 계획

## 1. 목표

모바일 주문과 PC 관리자 화면이 `Fresh Route` 디자인 콘셉트를 일관되게 따르고, 정보의 중요도와 사용자의 다음 행동이 명확한지 검증합니다.

## 2. 디자인 기준 문서

- `../service-planning/design-concept.md`
- `../service-planning/customer-order/mobile-screen-spec.md`
- `../service-planning/admin/pc-screen-spec.md`

구현과 기준이 충돌하면 디자인 콘셉트의 토큰을 우선하고, 화면별 행동과 정보 요구사항은 각 화면 구성 문서를 우선합니다.

## 6. 반응형 검증

### 모바일 360×800

- 가로 스크롤이 없어야 합니다.
- 메뉴명 두 줄과 가격이 겹치지 않아야 합니다.
- 하단 고정 버튼이 콘텐츠와 입력 오류를 가리지 않아야 합니다.
- 긴 알레르기·원산지 문구가 화면 밖으로 잘리지 않아야 합니다.

### 모바일 390×844, 430×932

- 카드 열 수와 간격이 불필요하게 넓어지지 않아야 합니다.
- 상단 버튼과 매장명이 겹치지 않아야 합니다.
- 모달과 옵션 목록이 화면 높이에 맞게 스크롤되어야 합니다.

### PC 1280×720

- 좌측 내비게이션과 본문이 겹치지 않아야 합니다.
- 주문 목록과 상세 패널의 주요 열이 보여야 합니다.
- 중요 버튼이 세로 스크롤 아래로 숨지 않아야 합니다.

### PC 1440×900 이상

- 콘텐츠가 지나치게 늘어나 가독성이 떨어지지 않아야 합니다.
- 표 열과 카드가 남는 공간을 균형 있게 사용해야 합니다.

## 7. 상태 디자인 검증

각 주요 화면에서 아래 상태를 반드시 촬영하고 비교합니다.

- 기본
- 로딩 중
- 빈 데이터
- 선택됨
- 비활성
- 품절
- 성공
- 주의
- 오류
- 네트워크 끊김
- 처리 결과 확인 중

검증 기준:

- 상태가 색상 외에 문구와 아이콘으로도 표현됩니다.
- 오류는 문제와 해결 방법을 함께 안내합니다.
- 비활성 버튼 주변에 사용할 수 없는 이유가 있습니다.
- 로딩 중 레이아웃이 크게 이동하지 않습니다.

## 9. 사용성 과제

테스터에게 설명 없이 아래 과제를 수행하게 합니다.

1. 레몬 딜 쉬림프 샌드위치를 포장 주문합니다.
2. 필수 옵션을 일부러 하나 빼고 다음 단계로 이동해 봅니다.
3. 장바구니에서 수량을 2개로 변경합니다.
4. 결제 실패 후 다시 결제를 시도합니다.
5. 관리자에서 신규 주문을 찾아 준비 완료로 변경합니다.
6. 특정 메뉴를 품절 처리하고 고객 화면에서 확인합니다.

관찰 항목:

- 과제 완료 여부
- 완료 시간
- 잘못 누른 횟수
- 도움을 요청한 지점
- 상태나 문구를 오해한 지점
- 테스터가 기대한 다음 행동

## 10. 디자인 합격 조건

- P0 디자인 항목에 FAIL이 없어야 합니다.
- 모바일 3개 크기와 PC 2개 크기에서 핵심 기능이 가려지지 않아야 합니다.
- 모든 오류·품절·진행 상태가 색상 없이도 구분되어야 합니다.
- 사용성 과제 1~6을 치명적인 도움 없이 완료할 수 있어야 합니다.
- 발견된 Low 시각 결함은 위치와 수정 권장값을 기록해야 합니다.
