# 서비스 기능 검증 계획

## 1. 목표

고객이 메뉴 선택부터 주문 상태 확인까지 완료할 수 있고, 관리자가 주문·메뉴·품절·매출·설정을 관리할 수 있는지 검증합니다. 고객과 관리자가 같은 데이터를 보고 같은 주문 상태를 공유하는지도 확인합니다.

## 2. 고객 모바일 P0 시나리오

### SV-C-001 정상 주문 완료

- 사전 조건: 주문 접수 중, 네트워크 정상, 판매 가능한 메뉴 존재
- 데이터: 바질 치킨 아보카도 샌드위치, 위트, 레귤러, 단품, 수량 1
- 단계:
  1. 모바일 주문 화면에 접속합니다.
  2. 매장 식사 또는 포장을 선택합니다.
  3. 메뉴를 선택하고 필수 옵션을 모두 선택합니다.
  4. 장바구니에 담고 주문 확인 화면으로 이동합니다.
  5. 결제 성공 시뮬레이션을 실행합니다.
- 기대 결과:
  - 메뉴, 옵션, 수량과 금액이 모든 화면에서 동일합니다.
  - 결제 버튼은 처리 중 다시 누를 수 없습니다.
  - 주문번호가 한 번만 생성됩니다.
  - 주문 상태 화면에 결제 완료 단계가 표시됩니다.

### SV-C-002 신규 시트 메뉴 주문

- 데이터: 레몬 딜 쉬림프 샌드위치, 기본 가격 7,900원
- 기대 결과:
  - 추천 목록과 샌드위치 목록에 표시됩니다.
  - 신메뉴 배지가 표시됩니다.
  - 상세 화면에 알레르기 `새우, 밀, 우유, 계란`이 표시됩니다.
  - 샌드위치 옵션 템플릿이 적용됩니다.

### SV-C-003 신규 음료 주문

- 데이터: 시트러스 민트 콤부차, 기본 가격 4,500원
- 기대 결과:
  - 추천 목록과 음료 목록에 표시됩니다.
  - 시즌 배지가 표시됩니다.
  - 음료 옵션 템플릿이 적용됩니다.

## 4. PC 관리자 P0 시나리오

### SV-A-001 신규 주문 처리

- 사전 조건: 고객이 결제 완료 주문을 생성한 상태
- 단계:
  1. 대시보드 신규 주문 건수를 확인합니다.
  2. 주문 관리에서 해당 주문을 엽니다.
  3. 주문을 접수하고 준비 중, 준비 완료로 변경합니다.
- 기대 결과:
  - 상태별 건수와 주문 목록이 함께 갱신됩니다.
  - 고객 주문 상태 화면도 같은 상태로 바뀝니다.
  - 변경 이력에 처리자와 시각이 남습니다.

### SV-A-002 메뉴 품절 동기화

- 단계:
  1. 판매 중 메뉴를 관리자에서 품절 처리합니다.
  2. 고객 화면에서 같은 메뉴를 확인합니다.
  3. 품절을 해제하고 다시 확인합니다.
- 기대 결과:
  - 고객 화면에 즉시 품절 상태가 반영됩니다.
  - 품절 메뉴는 장바구니에 새로 담을 수 없습니다.
  - 해제 후 다시 선택할 수 있습니다.

## 7. 비기능 검증

### 성능

- 첫 화면이 일반 로컬 환경에서 지연 없이 표시되어야 합니다.
- 메뉴 11개 렌더링 시 스크롤과 탭 전환이 끊기지 않아야 합니다.
- 상태 변경이 고객·관리자 화면에 1초 이내 반영되는지 관찰합니다.

### 안정성

- 새로고침 10회 후에도 메뉴 수와 저장 상태가 변하지 않아야 합니다.
- 동일 버튼을 빠르게 5회 눌러도 중복 주문이 생기지 않아야 합니다.
- 잘못된 저장 데이터가 있어도 앱 전체가 빈 화면이 되지 않아야 합니다.

### 보안과 개인정보

- 관리자 화면은 인증 상태 없이 보호 기능에 접근할 수 없어야 합니다.
- 비밀번호와 결제정보를 LocalStorage에 평문 저장하지 않아야 합니다.
- 오류 메시지에 내부 스택, 토큰, 개인정보가 표시되지 않아야 합니다.

## 8. 실행 기록 방법

각 테스트 ID별로 `validation-report-template.md`의 실행 기록 표에 상태, 실제 결과, 증거, 결함 ID를 기록합니다.
