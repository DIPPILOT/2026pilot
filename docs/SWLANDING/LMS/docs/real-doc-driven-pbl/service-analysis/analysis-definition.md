# 기본 분석 정의

## 1. 목적

샌드위치·음료 주문 서비스의 고객 행동, 주문 성과, 메뉴 성과, 매장 운영 상태를 일관된 기준으로 분석하기 위한 기본 정책입니다.

## 2. 분석 대상

### 고객 주문 분석

- 주문 화면 방문 수
- 주문 시작 수
- 메뉴 조회와 선택 수
- 장바구니 담기·수정·삭제 수
- 결제 진입·성공·실패 수
- 주문 완료와 주문 상태 조회 수
- 화면 단계별 이탈 수

### 메뉴 분석

- 메뉴별 조회 수
- 메뉴별 장바구니 전환율
- 메뉴별 주문 수량과 매출
- 옵션별 선택 수와 추가 매출
- 품절 발생 횟수와 품절 지속 시간
- 추천·신메뉴 배지가 선택에 미친 영향

### 매장 운영 분석

- 시간대별 주문 건수
- 주문 접수까지 걸린 시간
- 준비 완료까지 걸린 시간
- 지연 주문 비율
- 취소·환불 건수와 사유
- 모바일 주문 일시 중지 횟수와 지속 시간

### 서비스 품질 분석

- 결제 실패율
- 네트워크 오류율
- 데이터 동기화 실패율
- 화면별 오류 발생 수
- 중복 주문 방지 동작 횟수
- 사용 환경별 성공률

## 3. 핵심 지표 초안

| 지표 ID | 지표명 | 기본 계산식 | 집계 단위 |
|---|---|---|---|
| M-001 | 주문 전환율 | 결제 성공 주문 수 ÷ 주문 시작 수 × 100 | 일·주·월 |
| M-002 | 장바구니 전환율 | 장바구니 담기 세션 수 ÷ 메뉴 상세 조회 세션 수 × 100 | 일·메뉴 |
| M-003 | 결제 성공률 | 결제 성공 수 ÷ 결제 시도 수 × 100 | 일·결제수단 |
| M-004 | 평균 주문 금액 | 결제 완료 금액 ÷ 결제 완료 주문 수 | 일·매장 |
| M-005 | 평균 주문 상품 수 | 판매 수량 ÷ 결제 완료 주문 수 | 일·매장 |
| M-006 | 평균 준비 시간 | 준비 완료 시각−결제 완료 시각의 평균 | 일·시간대 |
| M-007 | 지연 주문 비율 | 기준 시간 초과 주문 수 ÷ 완료 주문 수 × 100 | 일·매장 |
| M-008 | 취소율 | 취소 주문 수 ÷ 결제 완료 주문 수 × 100 | 일·사유 |
| M-009 | 품절 영향 주문 수 | 품절 메뉴 조회 후 미주문 세션 수 | 일·메뉴 |
| M-010 | 메뉴별 매출 | 메뉴 기본가와 선택 옵션 금액의 합계 | 일·메뉴 |

## 4. 분석 기준 단위

### 세션

- 고객이 주문 링크에 접속한 시점부터 주문 완료, 이탈 또는 30분 무활동까지를 한 세션으로 봅니다.
- 같은 기기에서 새 주문을 시작하면 새 세션 ID를 생성합니다.
- 개인정보 대신 임의의 세션 식별자를 사용합니다.

### 주문

- 주문번호가 생성된 결제 성공 건을 기본 주문 단위로 봅니다.
- 결제 결과 확인 중인 건은 성공 여부가 확정될 때까지 별도 상태로 집계합니다.
- 취소 주문은 주문 수에는 포함하고 순매출에서는 제외합니다.

### 날짜와 시간

- 매장 현지 시간대를 기준으로 집계합니다.
- 일간 집계는 00:00~23:59입니다.
- 주문 시간은 결제 성공 시각을 기본으로 합니다.
- 준비 시간은 결제 성공부터 준비 완료까지로 계산합니다.

## 5. 이벤트 명명 규칙

형식은 `영역_대상_동작`의 소문자 스네이크 케이스를 사용합니다.

### 예시

- `order_session_started`
- `menu_list_viewed`
- `menu_detail_viewed`
- `cart_item_added`
- `checkout_started`
- `payment_succeeded`
- `payment_failed`
- `order_status_changed`
- `menu_sold_out`
- `admin_order_paused`

## 6. 공통 이벤트 속성

| 속성 | 타입 | 필수 | 설명 |
|---|---|---|---|
| event_id | string | 예 | 이벤트 중복 제거용 고유 ID |
| event_name | string | 예 | 정의된 이벤트 이름 |
| occurred_at | datetime | 예 | 이벤트 발생 시각 |
| session_id | string | 고객 이벤트 | 익명 세션 ID |
| store_id | string | 예 | 매장 ID |
| screen_name | string | 화면 이벤트 | 발생 화면 |
| order_id | string | 주문 이벤트 | 내부 주문 ID |
| menu_id | string | 메뉴 이벤트 | 메뉴 ID |
| actor_type | string | 예 | customer, staff, manager, system |
| app_version | string | 예 | 데이터 생성 버전 |
| device_type | string | 아니오 | mobile, desktop |

## 7. 데이터 품질 정책

- `event_id`가 같은 데이터는 한 번만 집계합니다.
- 필수 속성이 없는 이벤트는 정상 집계에서 제외하고 오류 건수에 포함합니다.
- 미래 시각 또는 비정상적으로 오래된 이벤트는 검토 대상으로 분리합니다.
- 주문 금액은 주문 원본 데이터와 일치해야 합니다.
- 메뉴 ID는 메뉴 기준 데이터에 존재해야 합니다.
- 정의되지 않은 이벤트 이름은 분석 저장소에 적재하기 전에 차단합니다.
- 데이터 지연 시간과 마지막 성공 수집 시각을 함께 관리합니다.

## 8. 개인정보와 민감정보

### 수집하지 않는 데이터

- 고객 이름과 전화번호
- 카드번호, 유효기간, CVC
- 결제 토큰과 인증값
- 비밀번호
- 정확한 기기 식별자
- 고객 요청사항의 원문을 분석 이벤트에 복제한 값

### 제한적으로 사용할 데이터

- 세션 ID는 임의 값으로 생성하고 개인과 연결하지 않습니다.
- 관리자 ID는 권한 감사 목적에 필요한 범위에서만 사용합니다.
- IP 주소와 사용자 에이전트는 보안 목적이 확정되기 전에는 저장하지 않습니다.

## 9. 분석 변경 관리

분석 정의를 변경할 때 아래 내용을 기록합니다.

- 변경일
- 변경한 지표 또는 이벤트 ID
- 변경 전·후 정의
- 과거 데이터 재계산 필요 여부
- 영향을 받는 API와 대시보드
- 적용 버전

## 10. 추후 결정 사항

- 분석 데이터 보관 기간
- 실시간 집계와 배치 집계의 구분
- 매장 간 비교 권한
- 관리자별 조회 권한
- 대시보드 도구와 데이터 저장소
- 이벤트 전송 실패 시 재시도 규칙
