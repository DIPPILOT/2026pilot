# Skill·Mission 콘텐츠 운영 기준

## 콘텐츠 역할

### Developer Skill

Skill은 AI Agent에게 구현을 위임하는 과제가 아니다. 개발자가 해당 일차의 기술 개념을 직접 이해하고 코드·설계·테스트를 작성하도록 구성한다.

1. 개발자가 AI 사용 전에 자신의 초안 또는 원인 가설을 작성한다.
2. AI는 완성본 작성자가 아니라 Tutor·Reviewer·반례 생성기로 사용한다.
3. 개발자는 AI 제안을 근거, 실행 결과, 테스트로 검증한 뒤 직접 수정한다.
4. 완료 산출물에는 구현 결과뿐 아니라 채택·기각 근거와 학습 내용을 포함한다.
5. 개발자가 결과를 자신의 언어로 설명할 수 있을 때 완료로 판단한다.

### Planner × Developer Mission

Mission은 기획자와 개발자가 AI Agent를 함께 사용할 때 발생하는 요구사항 누락, 근거 없는 가정, 해석 차이, 검증 및 책임 문제를 해결하는 협업 과제다.

1. AI 결과를 확인된 사실, AI의 가정, 누락 질문, 위험으로 분리한다.
2. 기획자는 사용자 가치, 정책, 범위, 업무 근거를 제시한다.
3. 개발자는 시스템 제약, 실패 사례, 보안·데이터 영향, 검증 증거를 제시한다.
4. AI는 결정을 대신하지 않고 선택지와 검증 질문을 구조화한다.
5. 최종 산출물에는 공동 결정, 근거, 담당자, 완료 조건, 재검토 시점을 기록한다.

## LMS 반영 구조

- `docs/shared/curriculum-content.js`: Day 1~10 Skill·Mission의 단일 콘텐츠 원본. Day 1은 기존 통합 실습실에서 이전한 추가 Mission 4개를 포함한다.
- `docs/shared/curriculum-cards.js`: 메인 강의실과 상세 Task 보드의 카드 동기화
- `docs/shared/learning-lab.html`: Developer Skill 및 Planner × Developer Mission 공용 실습실

카드 링크는 기존 Task·Mission 페이지를 재사용하지 않는다. 다음 형식의 고유 학습 단계로 연결한다.

```text
../shared/learning-lab.html?day={1..10}&type=skill&id={1..3}
../shared/learning-lab.html?day={1..10}&type=mission&id={1..4}
```

## PBL 카드 필수 구성

모든 Skill·Mission 카드는 설명이나 AI 사용법만 제시하지 않고 학생이 수업 시간에 바로 수행할 수 있는 다음 정보를 포함한다.

1. **연속 프로젝트:** Day 1~10 동안 이어지는 Streamly 서비스 개발 맥락
2. **해결할 문제:** 해당 카드에서 학생 팀이 해결해야 할 구체적인 문제 상황
3. **제공 자료:** 학생이 시작할 때 받는 Markdown, CSV, JSON, 코드, 로그 등의 파일명
4. **학생 수행 과제:** 조사·설계·구현·검증으로 이어지는 최소 3개의 실행 단계
5. **제출 산출물:** 코드, 다이어그램, 의사결정 기록 또는 검증 보고서
6. **완료 검수 기준:** 개수, 테스트 통과 여부, 근거 유무 등 관찰 가능한 완료 조건
7. **단계별 수행 설명:** 어느 자료의 어떤 부분을 확인하고, 무엇을 판단·작성하며, 어떤 증거를 남겨야 하는지 설명
8. **실제 산출물 예시:** 코드·표·Mermaid·테스트·공동 의사결정 기록 등 제출 형식과 구체성의 기준

Skill은 개인 또는 개발자 Pair가 직접 구현하고, Mission은 기획자–개발자 역할을 나눠 공동 Decision을 만드는 방식으로 진행한다.

## 검수 기준

- 각 Day의 메인 강의실과 상세 Task 보드에 Skill 3개, Mission 4개가 표시된다.
- Day 1에는 기본 Mission 4개와 기존 Codex 실습실에서 이전한 추가 Mission 4개, 총 8개가 표시된다.
- Skill 카드에는 개발자가 직접 익힐 기술과 검증 행동이 나타난다.
- Mission 카드에는 AI Agent 활용 과정의 협업 이슈와 기획·개발 역할이 나타난다.
- 모든 카드에 제공 자료 2개 이상, 학생 수행 단계 3개 이상, 관찰 가능한 검수 기준이 존재한다.
- 모든 수행 단계에 설명이 있고 모든 카드에 실제 산출물 예시가 존재한다.
- 서로 다른 카드가 같은 학습 단계 URL을 공유하지 않는다.
- AI가 만든 결과 자체를 완료로 인정하지 않고 사람의 판단 근거와 검증 기록을 요구한다.
